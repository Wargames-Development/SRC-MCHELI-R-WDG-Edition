## 改动 2：红外寻的（IsHeatSeekerMissile）的数据链制导

### 2.1 目标武器类型

同时满足以下条件的 AA 导弹（AAMissile）和 AT 导弹（ATMissile）：

```
IsHeatSeekerMissile = true
activeRadar   = false
passiveRadar  = false
semiActiveRadar = false
antiRadiationMissile = false
```

即：纯红外寻的导弹（无任何雷达制导能力），通过数据链获得雷达辅助引导能力。

### 2.2 与现有雷达数据链的关系

| 项目 | 现有雷达数据链 | 本次红外数据链 |
|------|--------------|---------------|
| 适用武器 | `activeRadar/passiveRadar/semiActiveRadar = true` 的雷达弹 | `isHeatSeekerMissile=true` 且全部雷达标志为 false 的红外弹 |
| 发射后行为 | 持续中继：雷达脱锁 → 导弹失联（Passive/SemiActive）或主动捕获（Active） | **射后不管**：仅发射瞬间装订目标坐标，雷达脱锁不影响，雷达换锁不影响 |
| 距离限制 | 无（受 `maxLockOnRange` 约束） | **硬限制 350 米**，超距禁止发射 |
| BVR 框 | 双红圈（`drawDualRedRings`） | 单红圈 + 闪烁 |
| 数据链门限环 | 有（`drawDataLinkFovRing`，白色半圆环） | **复用**同样的白色半圆环 |
| 开关方式 | `enableDataLink` + `KeySwWeaponMode` 切换 | **复用**同一按键、同一机制 |

**互斥关系**：
- 红外数据链与雷达数据链**不冲突**——它们作用于不同的武器类型子集
- 红外数据链的 `isHeatSeekerMissile && !activeRadar && !passiveRadar && !semiActiveRadar && !antiRadiationMissile` 与现有雷达数据链的条件天然互斥
- 现有 `shouldBlockShotByDataLink()` 门控中：

  ```java
  // 当前条件：只让 active/passive/semiActive 进入数据链发射门控
  if (getInfo().antiRadiationMissile || !(getInfo().activeRadar || getInfo().passiveRadar || getInfo().semiActiveRadar)) {
      return false;  // ← 红外弹走这个分支直接跳过
  }
  ```

  → 需要在红外分支前**不跳过**，新增一条针对红外弹的距离门控

### 2.3 发射门控逻辑（新增）

#### 门控 A：雷达未锁定

条件：玩家未通过雷达锁定任何目标（`trackingTargetId <= 0`）。

行为：
- 禁止发射
- 提示（中文）：`"请先使用雷达锁定目标"`
- 提示（英文）：`"Lock a target with radar first"`

#### 门控 B：距离超限

条件：雷达已锁定目标，但目标距离 > 350 米。

行为：
- 禁止发射
- 提示（中文）：`"距离过远，红外导引头无法截获目标"`
- 提示（英文）：`"Target too far, IR seeker cannot acquire"`

#### 门控 C：通过

条件：雷达已锁定目标、且目标距离 ≤ 350 米。

行为：
- 允许发射
- 导弹的 `dataLinkRelayMode = true`
- 导弹记录 `dlRelayEverEnabled = true`
- 发射时从雷达读取当前目标实体 ID 并写入 `setTargetEntity()`
- **之后不再更新目标**（射后不管）

### 2.4 发射后行为（射后不管）

与现有雷达数据链的关键差异：

| 阶段 | 现有雷达数据链 | 红外数据链 |
|------|--------------|----------|
| 发射 | 写入目标 + 启动中继 | 写入目标 + 启动中继 |
| 飞行中 | 每帧 `updateDataLinkTargetsFromRadar()` 与雷达状态同步 | **不调用 `updateDataLinkTargetsFromRadar()`** |
| 雷达脱锁 | 被动/半主动 → 失联 | **不脱锁**，继续追踪原目标 |
| 雷达换锁 | 主动 → 跟随雷达新目标 | **不换目标**，继续追踪原目标 |
| 导弹自导 | 依赖雷达弹自身制导（主动/被动/半主动） | 飞行中仅使用红外导引头获取的坐标 + 数据链装订的目标位置做 `guidanceToPos()` |

实现方式：
- 在 `MCH_WeaponBase` 或 `MCH_EntityBaseBullet` 新增标志 `heatSeekerDatalinkMode`
- 该标志为 true 时，跳过 `updateDataLinkTargetsFromRadar()` 的更新循环
- 在 `onUpdateArmGuidance()` 中（对红外弹来说就是常规导引分支），按 `guidanceToPos()` 追踪发射时装订的 `targetEntity.posX/Y/Z`（或最后已知位置）

### 2.5 BVR 框渲染

#### 单红圈（区别于雷达数据链的双红圈）

```
现有雷达数据链：
  drawDualRedRings(r1, r2)  → 两个同心红圈

本次红外数据链：
  画一个更大的单红圈（半径 ≈ r2）
```

具体修改：

```java
// drawMarkerCore() 中，现有逻辑：
if (showDataLinkRings) {
    drawDualRedRings(half * 0.88F, half * 1.03F, alpha);
}

// 新增红外单圈分支：
if (showDataLinkRings) {
    if (isHeatSeekerDatalink) {
        drawSingleRedRing(half * 1.20F, alpha);  // 更大的单圈
    } else {
        drawDualRedRings(half * 0.88F, half * 1.03F, alpha);
    }
}
```

#### 闪烁规则

| 条件 | 圈色 | 不透明度 | 闪烁周期 |
|------|------|---------|---------|
| 锁定 + 距离 ≤ 350m | 红色 | 100% ↔ 50% | 每 5 tick 交替 |
| 锁定 + 距离 > 350m | 白色 | 100% ↔ 50% | 每 5 tick 交替 |

实现方式（复用现有 `blinkAlpha` 机制）：

```java
// MCH_RenderRWR.drawDataLinkFovRing() 已有类似实现：
float blinkAlpha = ((tick / 5L) % 2L == 0L) ? 1.0F : 0.45F;
```

在 `drawSingleRedRing()` 中：
```java
long tick = ...;
float alpha = ((tick / 5L) % 2L == 0L) ? 1.0F : 0.5F;
GL11.glColor4f(1.0F, 1.0F, 1.0F, alpha);  // 白色：距离 > 350m
GL11.glColor4f(1.0F, 0.0F, 0.0F, alpha);  // 红色：距离 ≤ 350m
```

#### BVR 框显示条件

红外数据链 BVR 框的 `showDataLinkRings` 条件与现有相同：
```java
boolean showDataLinkRings = dataLinkMode && inMissileFov && (isRadarSelectedOrTracking || isFireControlLocked);
```

唯一的区别是 `dataLinkMode` 的判定扩展为：
```java
boolean dataLinkMode =
    // 现有雷达数据链
    (currentWi.enableDataLink && (currentWi.onlyDataLink || currentWs.isDataLinkMode()) && !currentWi.antiRadiationMissile
     && (currentWi.activeRadar || currentWi.passiveRadar || currentWi.semiActiveRadar))
    ||
    // 新增红外数据链
    (currentWi.isHeatSeekerMissile && !currentWi.activeRadar && !currentWi.passiveRadar && !currentWi.semiActiveRadar && !currentWi.antiRadiationMissile
     && currentWs.isDataLinkMode());
```

#### 数据链门限环

复用现有 `drawDataLinkFovRing()` 中的白色半圆环：
- 显示条件同样扩展为包含红外数据链
- 环大小不变（基于 `getHudPreferredMissileFovDeg()`）
- 闪烁逻辑不变（5 tick 周期）

### 2.6 数据链开关/切换

修改 `MCH_AircraftClientTickHandler` 中的 `canDataLinkToggle` 条件：

```java
boolean canDataLinkToggle = info != null && info.enableDataLink && !info.onlyDataLink
    && (
        (info.activeRadar || info.passiveRadar || info.semiActiveRadar)
        ||
        (info.isHeatSeekerMissile && !info.activeRadar && !info.passiveRadar && !info.semiActiveRadar)

    && !info.antiRadiationMissile;
```

即：按下 `KeySwWeaponMode` 时，红外弹也可以进入/退出数据链模式。

### 2.8 不会影响现有逻辑的原因（边界确认）

| 现有代码 | 会不会被影响 | 原因 |
|---------|------------|------|
| `activeRadar` 数据链弹 | **不会** | 条件互斥，红外条件是 `!activeRadar && !passiveRadar && !semiActiveRadar` |
| `passiveRadar` 数据链弹 | **不会** | 同上 |
| `semiActiveRadar` 数据链弹 | **不会** | 同上 |
| ARM（`antiRadiationMissile=true`） | **不会** | 红外数据链条件要求 `!antiRadiationMissile` |
| `shouldBlockShotByDataLink()` | **不会** | 新增红外分支独立于现有分支 |
| `updateDataLinkTargetsFromRadar()` | **不会** | 红外弹 `heatSeekerDatalinkMode=true` 时跳过此函数 |
| `drawDataLinkFovRing()` | **不会** | 只是扩展显示条件，现有武器行为不变 |
| `drawDualRedRings()` | **不会** | 仅在 `showDataLinkRings=true` 时调用，红外弹不进入该分支 |
| `canDataLinkToggle` | **扩展** | 只是加了 `||` 条件，现有武器不受影响 |
| 武器 `mode` 编号 | **不会** | 数据链模式不占用 `currentMode` |

## 改动 3：巡航弹道适用范围扩展

### 3.1 当前实现

`shouldUseArmCruise()` 和 `guideArmToPosition()` 只存在于：
- `MCH_EntityAAMissile`（ARM 分支内）
- `MCH_EntityATMissile`（ARM 分支内）

调用条件：**仅在 `antiRadiationMissile=true` 的制导循环中被调用**。

### 3.2 需求

巡航弹道（保持高度 + 仅水平偏航修正 → 近目标后全三维俯冲）扩展到以下三种场景：

| 序号 | 导弹类型 | 触发条件 | 巡航参数复用 |
|------|---------|---------|------------|
| A | ATM（`ATMissile`）数据链制导弹 | `enableDataLink == true` 且 `isDataLinkMode() == true` | 复用现有 `armCruiseEnable/StartDistance/TerminalRadius/TerminalHeight` |
| B | GPS 导弹（`ASMissile`，`isGPSMissile=true`） | 无条件（或 if `isGPSMissile=true`） | 复用或新增 `cruiseEnable` 系列参数 |
| C | 激光制导 TV 弹（`TvMissile`，`laserGuidance=true`） | `laserGuidance == true` 且在激光导引阶段 | 复用 `armCruiseEnable` 系列参数 |

### 3.3 设计

#### 巡航导引方法抽取

将 `shouldUseArmCruise()` 和 `guideToPositionWithCruise()` 从 ARM 专属提取为 `MCH_EntityBaseBullet` 的公共方法：

```java
// MCH_EntityBaseBullet.java 新增：
public boolean shouldUseCruise(double tx, double ty, double tz) {
    if (!getInfo().armCruiseEnable) {
        return false;
    }
    double dx = tx - this.posX;
    double dy = ty - this.posY;
    double dz = tz - this.posZ;
    double dist = Math.sqrt(dx * dx + dy * dy + dz * dz);
    if (dist <= getInfo().armCruiseStartDistance) {
        return false;
    }
    double horizontal = Math.sqrt(dx * dx + dz * dz);
    if (horizontal <= getInfo().armCruiseTerminalRadius && Math.abs(dy) <= getInfo().armCruiseTerminalHeight) {
        return false;
    }
    return true;
}

public void guidanceToPosWithCruise(double tx, double ty, double tz) {
    if (shouldUseCruise(tx, ty, tz)) {
        this.guidanceToPos(tx, this.posY, tz);
    } else {
        this.guidanceToPos(tx, ty, tz);
    }
}
```

这样 `MCH_EntityAAMissile.guideArmToPosition()` 和 `MCH_EntityATMissile.guideAtToPosition()` 可以直接调用基类方法。

#### A：ATM 数据链制导弹

**修改点**：`MCH_EntityATMissile.onUpdate()` / `MCH_EntityATMissile` 的数据链导引分支。

现有 ATM 数据链导引（在 `MCH_EntityATMissile` 的常规 `onUpdate` 中）：
```java
// 非 ARM 的 ATM 数据链导引，现有代码：
if (this.getCountOnUpdate() > this.getInfo().rigidityTime) {
    guidanceToPos(targetPosX, targetPosY, targetPosZ);  // 直接导引
}
```

改为：
```java
if (this.getCountOnUpdate() > this.getInfo().rigidityTime) {
    if (this.isDataLinkRelayMode() && this.getInfo().armCruiseEnable) {
        guidanceToPosWithCruise(targetPosX, targetPosY, targetPosZ);  // 带巡航
    } else {
        guidanceToPos(targetPosX, targetPosY, targetPosZ);  // 原样
    }
}
```

**条件**：
- `this.isDataLinkRelayMode() == true`（数据链模式下才启用巡航）
- 非数据链模式 → 原样 `guidanceToPos()`，不受影响

#### B：AS GPS 导弹

**修改点**：[MCH_EntityASMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityASMissile.java) 的 `onUpdate()` 中 `guidanceToPos()` 调用处（约 L96-L100）。

现有代码：
```java
if (getInfo().lockEntity) {
    // ...扫描附近实体...
    Vec3 aim = computeBallisticAimPoint(targetPosX, targetPosY, targetPosZ);
    guidanceToPos(aim.xCoord, aim.yCoord, aim.zCoord);
} else {
    Vec3 aim = computeBallisticAimPoint(originTargetPosX, originTargetPosY, originTargetPosZ);
    guidanceToPos(aim.xCoord, aim.yCoord, aim.zCoord);
}
```

改为：
```java
if (getInfo().lockEntity) {
    Vec3 aim = computeBallisticAimPoint(targetPosX, targetPosY, targetPosZ);
    if (getInfo().armCruiseEnable) {
        guidanceToPosWithCruise(aim.xCoord, aim.yCoord, aim.zCoord);
    } else {
        guidanceToPos(aim.xCoord, aim.yCoord, aim.zCoord);
    }
} else {
    Vec3 aim = computeBallisticAimPoint(originTargetPosX, originTargetPosY, originTargetPosZ);
    if (getInfo().armCruiseEnable) {
        guidanceToPosWithCruise(aim.xCoord, aim.yCoord, aim.zCoord);
    } else {
        guidanceToPos(aim.xCoord, aim.yCoord, aim.zCoord);
    }
}
```

**边界条件**：
- GPS 巡航与现有的 `ballisticMissile`（高抛弹道）+ `ballisticLateralSine`（横向机动）**不冲突**：
  - 巡航段控制的是**俯仰方向**（保持高度）
  - 横向机动控制的是**水平方向**（正弦偏移）
  - 两者叠加：巡航段保持高度的同时可以做横向摆动
  - 进入终端段后两者同时关闭，全三维导引
- `armCruiseEnable=false` 时完全不变
- GPS 导弹的 `computeBallisticAimPoint()` 返回的已经是经过抛物线/横向机动计算的目标点，`guidanceToPosWithCruise` 在其基础上进一步锁定 Y

**建议**：GPS 巡航的 `armCruiseStartDistance` 建议调大（如 300~500 米），因为 GPS 导弹通常是远距离武器。

#### C：TV 激光制导导弹

**修改点**：[MCH_EntityTvMissile.java](file:///d:/MCHR/MCH-Reforged/src/main/java/mcheli/weapon/MCH_EntityTvMissile.java) 的 `onLaserGuide()` 中。

现有代码：
```java
public void onLaserGuide(double x, double y, double z) {
    guidanceToPos(x, y, z);
}
```

改为：
```java
public void onLaserGuide(double x, double y, double z) {
    if (this.getInfo() != null && this.getInfo().armCruiseEnable) {
        guidanceToPosWithCruise(x, y, z);
    } else {
        guidanceToPos(x, y, z);
    }
}
```

**边界条件**：
- 仅 `laserGuidance=true` 时进入激光导引分支
- 激光导引阶段：`onLaserGuide()` 在每 tick 被调用，传入当前激光指示点坐标
- 巡航段锁定 Y 轴（保持当前高度），激光点移动时只跟踪水平方向
- 进入终端圆柱（R=50, H=1024）后恢复全三维跟踪
- 终端圆柱参数与 ARM 巡航相同，直接复用

### 3.3 配置说明

复用现有 `armCruise*` 参数，不改武器配置文件格式：

```properties
AntiRadiationMissile = false
; 以下巡航参数对数据链 AT 弹、GPS 弹、激光 TV 弹同样生效

ArmCruiseEnable = false
ArmCruiseStartDistance = 150.0
ArmCruiseTerminalRadius = 50.0
ArmCruiseTerminalHeight = 1024.0
```

### 3.4 不影响现有行为的原因

| 现有代码 | 受影响？ | 原因 |
|---------|---------|------|
| ARM 巡航 `guideArmToPosition()` | **不会** | 改为调用基类 `guidanceToPosWithCruise()`，逻辑不变 |
| ARM 巡航 `guideAtToPosition()` | **不会** | 同上 |
| 非数据链 ATM 普通导引 | **不会** | 条件 `this.isDataLinkRelayMode() == true` 才巡航 |
| 非数据链 AT 弹 | **不会** | 非数据链模式不巡航 |
| 非 GPS 的 AS 弹 | **不会** | `armCruiseEnable=false` 时不进入巡航分支 |
| 非激光制导的 TV 弹 | **不会** | TV 模式（`isTVMissile=true`）不进入 `onLaserGuide()` |
| 现有 `ballisticMissile` 高抛 | **不会** | GPS 巡航仅在 `guidanceToPos()` 外层封装，不影响 `computeBallisticAimPoint()` 的抛物线计算 |

## 边界条件汇总

### 改动 2 边界

| 边界 | 处理 |
|------|------|
| 雷达未锁定 + 红外数据链 | 禁止发射，提示 |
| 雷达锁定 + 距离 > 350m + 红外数据链 | 禁止发射，提示 |
| 雷达锁定 + 距离 ≤ 350m + 红外数据链 | 允许发射，射后不管 |
| 雷达脱锁后 | 导弹继续追踪原目标（不丢失） |
| 雷达切换到新目标 | 导弹不跟踪新目标 |
| 导弹发射后切换数据链模式 | 禁止；已在空中的导弹不受模式切换影响 |
| 红外弹 + 非数据链模式 | 完全保持原红外弹行为 |

### 改动 3 边界

| 边界 | 处理 |
|------|------|
| atm 数据链 + 巡航 + 目标在终端圆柱内 | 不巡航，直接全三维导引 |
| atm 非数据链 + 巡航开启 | 不巡航，因为 `isDataLinkRelayMode()==false` |
| GPS 巡航 + 横向机动 | 同时生效，巡航锁 Y、横向机动锁 XZ |
| GPS 巡航 + 不开启 `armCruiseEnable` | 完全不变 |
| TV 激光 + 巡航 + 激光点大幅移动 | 巡航段仅在水平面追踪，终端段恢复全三维 |
| TV 激光 + 非激光模式（TV目视） | 不走激光巡航分支 |

## 调研：BVR 框渲染

BVR（超视距）框的渲染在 `MCH_RenderBVRLockBox.java` 中，全在 `RenderWorldLastEvent` 里画。

### 渲染的实体来源

所有实体数据来自客户端缓存 `MCH_EntityInfoClientTracker.getAllTrackedEntities()`，包含所有已知载具和导弹的位置快照。

### 导弹 BVR 框 vs 载具 BVR 框的差异

| 项目 | 普通载具（飞机/坦克） | 导弹 |
|------|---------------------|------|
| **纹理** | `BVRLockBox.png`（绿/红框） | `MSL.png`（导弹专用纹理） |
| **高亮纹理** | 不叠加 | 高亮时再叠一层 `BVRLockBox.png` |
| **文字颜色** | 绿色 `0x00FF00`（非选中），红色 `0xFF0000`（被跟踪） | 固定红色 `0xFF0000` |
| **是否强制显示** | 仅 `selected/tracking/lock` 时必显示，否则需 `canRenderEntity` 通过 | **总是显示**（只要距离 < 4096m） |
| **距离限制** | `radarMaxTargetRange` | `min(4096, radarMaxTargetRange)` |
| **锁定环** | 数据链模式下的双红圈 | 数据链模式下的双红圈（相同） |
| **HUD 混合** | 近距离 900m 以内 HUD 混合 | 不同（导弹框始终保持世界渲染） |
| **文字** | `[目标名 距离m]` | `[MSL名 距离m]` |

代码出处（`MCH_RenderBVRLockBox.java`）：
- `isMSL` 判断：`isMissile(entity.entityClassName)` → 分出导弹和载具
- 导弹纹理：`MSL.png`，高亮时再叠 `FRAME`
- 载具纹理：`FRAME`（`BVRLockBox.png`）
- 强制显示：`isMSL` 时即使没有 `selected/tracking` 也渲染（`canRenderEntity` 对导弹返回 true 的条件更宽松）
- 导弹最大显示距离：`missileDisplayMaxRange = min(4096, radarMaxTargetRange)`

### 雷达面板上的导弹显示

`MCH_RenderRWR.renderRadarMissileOverlays()` 在雷达 GUI 面板上画：
- **自己发射**的雷达弹用红点 `0xFF4040` 显示在面板上
- 导弹用虚线/实线连向目标（数据链虚线，主动捕获后实线）
- 导弹目标如果是载具则显示目标图标

### BVR 框显示流程总结

```
RenderWorldLast
  → 遍历所有已知实体（载具+导弹）
  → 判断 canRenderEntity
      → 载具：需要被雷达扫描到 + 不干扰
      → 导弹：距离 20m~4096m 之间即可
  → 渲染 BVR 框
      → 导弹用 MSL.png（固定红色）
      → 载具用 BVRLockBox.png（绿框→红框当 locked）
  → 数据链双红圈：仅当 selected/tracking 且 inMissileFov
```

## 调研：AAmissile 与 ATmissile 的视距内锁定框（Pre-Aim Circle）

### AA/AT 导弹的锁定框——就是这个绿色方框（修正）

你说的绿色方框找到了。不在 BVR 框、不在激光框，在 `MCH_RenderAircraft.java`（约 870 行）。

#### 这是怎么渲染的

飞机/载具每帧渲染时（`RenderAircraft.renderEntity` 路过），对附近每个实体做以下检查：

```
1. 当前武器的 guidanceSystem 是否存在
2. guidanceSystem.canLockEntity(entity) 是否为 true
   → 红外弹：飞机、坦克、**MCH_EntityFlare（热焰弹）** 都返回 true
   → 雷达弹：飞机、坦克、**MCH_EntityChaff（箔条）** 都返回 true
3. 通过后 → 在实体位置画一个方框
```

#### 方框样式

| 状态 | 颜色 | 线宽 |
|------|------|------|
| 可锁定但还没锁上 | **绿色** | 1.5× |
| 已经锁定（lockCount 满了） | **红色** | 2.5× |
| 超出导引头范围（pdHDN 角度太大） | **半透明**（alpha=0.2） | — |

- 方框大小：根据实体尺寸动态计算（`max(width, height) * 20`），飞机/flare/chaff **再翻倍**
- 方框下方有距离文字
- 这个框在 3D 世界里画，会跟随实体位置移动

#### 关键代码位置

```java
// MCH_RenderAircraft.java ~870行
if (gs.canLockEntity(entity)) {  // 检查能不能锁
    // ...绘制方框
    if (isLockEntity) {
        tessellator.setColorRGBA_F(1.0F, 0.0F, 0.0F, alpha); // 红色=已锁定
    } else {
        tessellator.setColorRGBA_F(0.0F, 1.0F, 0.0F, alpha); // 绿色=可锁定
    }
    // 画方框（GL_LINE_LOOP）
    tessellator.addVertex(-size - 1.0F, 0.0D, 0.0D);
    tessellator.addVertex(-size - 1.0F, size * 2.0F, 0.0D);
    tessellator.addVertex(size + 1.0F, size * 2.0F, 0.0D);
    tessellator.addVertex(size + 1.0F, 0.0D, 0.0D);
    tessellator.draw();
    // 下方显示距离
    String text = " " + distanceText;
    fontRenderer.drawString(text, ...);
}
```

#### 和 BVR 框的关系

这段代码有个过滤条件：
```java
if (wi != null && acInfo != null && acInfo.enableBVR && distance < wi.minRangeBVR) {
    return;  // BVR 范围内不渲染这个方框（交给 BVR 框渲染）
}
```
意思是：如果载具开了 BVR 且目标在 BVR 最小范围内，这个方框**不画**，由 BVR 框（`MCH_RenderBVRLockBox`）接管。
如果没开 BVR，或者距离超过了 minRangeBVR，就用这个方框。

所以你看到的 flare/chaff 带绿色方框，是因为：
 1. 红外弹的 `canLockEntity` 直接返回 true 给 `MCH_EntityFlare`
 2. 雷达弹的 `canLockEntity` 直接返回 true 给 `MCH_EntityChaff`
 3. 这个渲染循环对每个世界实体都跑一遍检查，flare/chaff 在里面就能画出框

## 必须修复的 bug：导弹 BVR 框高亮叠加错误

### 现象

导弹打出去后，BVR 框一直显示**两层**（`MSL.png` 上叠 `BVRLockBox.png`），即使没有被雷达选中或锁定。

### 根因

`MCH_RenderBVRLockBox.java` 中：

```java
boolean highlight = isMSL || isRadarSelectedOrTracking || isFireControlLocked;
```

由于 `isMSL` 直接让 highlight=true，所有飞行中的导弹 BVR 框都在叠层。但正确的行为是——**只有被雷达选中/锁定的导弹才应该叠层**。

### 修复

```java
// 改前（bug）：
boolean highlight = isMSL || isRadarSelectedOrTracking || isFireControlLocked;

// 改后：
boolean highlight = isRadarSelectedOrTracking || isFireControlLocked;
```
