# 自研结构导入导出器开发建议（2026-04-17）

## 1. 背景与目标

- 当前痛点：跨存档粘贴时，`mcheli` 配置方块可能变成其他方块。
- 根因：通用工具链在 `1.7.10` 下常落到数字 ID 语义，跨世界 remap 后会错位。
- 目标：保留 `blocks/*.txt` 配置便利性，同时保证结构跨地图放置不变块。

## 2. 结论（先回答“难不难”）

- 结论：能做，难度中等，不是“做不了”。
- 如果要求：
  - 只做最小可用（捕获+放置+基础校验）：难度中等偏低，1-2 个开发阶段可落地。
  - 做完整生态（兼容导入 `.schem`、双向转换、自动修复、性能优化）：难度中等偏高。
- 核心点不在“写文件”，而在“方块语义映射与 TileEntity/NBT 保真”。

## 3. 推荐总体方案

- 建模阶段继续用创世神。
- 最终资产必须经过 MCHR 自有链路：
  - `capture` 从世界捕获结构。
  - `normalize` 规范化为名称语义（而不是数字 ID）。
  - `place` 用当前世界映射安全放置。
- 对 `mcheli` 关键块（生成器/航点）做后处理校验，确保 `BlockInfoName` 正确。

## 4. 文件格式建议（先务实）

- 元数据：`txt`（和你当前项目风格一致）。
- 方块体：`nbt` 或二进制块数据（性能更好）。
- 推荐目录：
  - `assets/mcheli/structures_runtime/meta/*.txt`
  - `assets/mcheli/structures_runtime/blob/*.nbt`

## 5. 命令建议（第一批）

- `/mcheli struct capture <name> <x1> <y1> <z1> <x2> <y2> <z2>`
  - 捕获区域结构，写入自有资产。
- `/mcheli struct place <name> <x> <y> <z> [rot=0|90|180|270] [mirror=none|x|z]`
  - 按名称语义放置结构。
- `/mcheli struct validate <name>`
  - 校验未知方块、非法参数、关键块 NBT 缺失。
- `/mcheli struct list`
  - 列出现有结构资产。
- `/mcheli spawnerfreeze true|false|status`
  - 捕获/放置前后冻结生成器，避免实体干扰。

## 6. 开发分阶段建议

- 阶段A（MVP）：
  - 做 `capture/place/list`。
  - 普通方块按 `modid:block + meta` 存取。
  - 关键块写入并校验 `BlockInfoName`。
- 阶段B（质量）：
  - 做 `validate`。
  - 增加失败统计日志（成功数/跳过数/修复数）。
- 阶段C（互操作）：
  - 增加“读取 `.schem` 后转自有格式”的单向转换器。
  - 明确 `.schem` 只作输入，不作为最终发布件。

## 7. 风险与控制

- 风险：TileEntity NBT 丢失导致关键块行为不对。
  - 控制：放置后立即做 TE 二次校验和修复。
- 风险：未知方块名在目标环境不存在。
  - 控制：`validate` 报告 + 放置时回退策略（跳过/替换）。
- 风险：大结构放置卡顿。
  - 控制：分批放置（每 tick 限额）与日志进度。

## 8. 你的问题的直接答案

- “我们没有自己的 `.schem` 导入/导出器，这点难做吗？”
- 答：不需要一步到位做完整 `.schem` 双向器。
- 最佳路径是先做“自有格式捕获/放置”，再做“`.schem` 单向导入转换”。
- 这样开发风险最低，且最快解决“跨地图变块”核心问题。

## 9. 验收标准

- 同一结构在两张不同存档放置后，`mcheli` 关键方块类型与 `BlockInfoName` 一致。
- `validate` 能输出清晰问题清单。
- 放置日志可追踪：总方块数、失败数、修复数、耗时。

## 10. 开发步骤（可直接执行）

1. 搭好 MVP 骨架：冻结范围（先不做 `.schem` 双向），定义 `meta/*.txt + blob/*.nbt` 格式和 `Version=1`，同时完成 `StructureMeta/StructureBlob/StructureIO` 基础读写。
2. 打通核心命令链：一次性实现 `capture/place/list`，其中 `capture` 负责采集方块+meta+TileEntity NBT，`place` 负责按名称语义放置并支持 `rot=0|90|180|270`。
3. 做关键块可靠性：在放置后加入 `mcheli` 关键块修复器，自动补/修 `BlockInfoName`，避免功能块落地后失效。
4. 做质量与可观测：实现 `validate`，并接入放置统计日志（总数、跳过、修复、耗时）用于调试和回归。
5. 做跨存档验收：在两张独立地图重复 `capture -> place` 回归，确认“不变块”目标达成。
6. 最后做互操作增强：阶段C再加 `.schem` 单向导入（palette 名称转自有格式），不阻塞 MVP 上线。

## 11. 命令优先级（建议）

- 第一批（必须）：
  - `/mcheli struct capture <name> <x1> <y1> <z1> <x2> <y2> <z2>`
  - `/mcheli struct place <name> <x> <y> <z> [rot=0|90|180|270] [mirror=none|x|z]`
  - `/mcheli struct list`
- 第二批（增强）：
  - `/mcheli struct validate <name>`
  - `/mcheli struct doctor <name>`
- 配套命令：
  - `/mcheli spawnerfreeze true|false|status`

## 12. 阶段验收口径

- 功能正确：
  - 同一结构跨两张存档放置后，关键 `mcheli` 方块类型和 `BlockInfoName` 一致。
- 可观测性：
  - `validate` 报告包含结构名、问题类型、坐标。
  - 放置日志包含成功数、失败数、修复数、耗时。
- 可维护性：
  - 结构格式带版本号，旧版本可被识别并给出升级提示。

## 13. 命令介绍（当前可用）

- `/mcheli struct capture <name> <x1> <y1> <z1> <x2> <y2> <z2>`
  - 作用：把选区保存为自有结构资产（`meta/*.txt + blob/*.nbt`）。
  - 说明：只保存非空气方块，并保留 TileEntity NBT。
- `/mcheli struct place <name> <x> <y> <z> [rot]`
  - 作用：按名称语义放置结构，支持旋转 `0/90/180/270`。
  - 说明：放置后自动执行关键块修复器，修复 `BlockInfoName`。
- `/mcheli struct list`
  - 作用：列出已保存结构名。
- `/mcheli struct validate <name>`
  - 作用：静态校验结构资产质量。
  - 检查项：未知方块、越界坐标、`BlockInfoName` 缺失/非法、尺寸不一致。
- `/mcheli struct verify <name> <x> <y> <z> [rot]`
  - 作用：对比“结构资产”与“世界落地结果”的一致性。
  - 统计项：`mismatchBlock`、`mismatchMeta`、`mismatchBlockInfo`、`missingChunk`。
- `/mcheli struct importschem <name> <schemPath>`
  - 作用：把 `.schem` 单向导入为自有结构资产。
  - 说明：支持绝对路径，或从 `config/mcheli/structures_runtime/import/` 读取文件名。
- `/mcheli spawnerfreeze true|false|status`
  - 作用：冻结/解冻配置生成器，避免导出导入时刷实体干扰。

## 14. 构建失败记录（Terminal#1-142）

- 现象：
  - `compileJava` 报错：`getListOfStringsMatchingLastWord` 需要 `String[]`，实际传入了 `List<String>`。
  - 报错位置：`MCH_Command.java` 的 `struct` 命令补全分支。
- 原因：
  - 命令补全 API 选型不匹配，`List<String>` 应走 `getListOfStringsFromIterableMatchingLastWord`。
- 修复：
  - 已将 `struct` 的三个补全点改为 `getListOfStringsFromIterableMatchingLastWord`。
  - 变更文件：`src/main/java/mcheli/command/MCH_Command.java`。
