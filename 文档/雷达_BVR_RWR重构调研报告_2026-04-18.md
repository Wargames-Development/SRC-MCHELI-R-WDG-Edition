- 梳理当前 MCH-Reforged 内雷达、BVR、RWR 的真实代码链路。

## 3. 与现实雷达机制的主要差距

下面按“现实可简化模型”对比，不追求硬核电磁仿真，但要保持行为逻辑正确。

### 3.1 传感器层（搜索 vs 跟踪）

- 现实：
  - 搜索雷达（RWS）与跟踪雷达（STT/TWS）是不同工作模式。
  - 扫描体积（方位/俯仰/距离）与刷新率影响目标稳定性。
- 当前：
  - 缺少统一“传感器状态机”，多处直接取实体列表判定。
  - 扫描刷新、跟踪维持、丢失重捕获规则分散。

### 3.2 制导链（主动/半主动/被动）

- 现实：
  - 半主动（SARH）依赖母机持续照射。
  - 主动（ARH）有中段数据链 + 末段自导（常见 HPRF 终端）。
  - 被动/反辐射看辐射源而非通用目标列表。
- 当前：
  - 半主动有角度/距离保持，但缺“明确照射源状态”抽象。
  - 主动与半主动在搜索逻辑上存在重叠/混用。
  - BVR 中段指令链路未形成稳定闭环（`PacketLockTargetBVR`未成为主链）。

### 3.3 RWR 与威胁等级

- 现实：
  - RWR区分搜索波束、跟踪照射、导弹发射告警（不同优先级和音频节奏）。
  - 方位精度与距离信息通常是“有限可信度”。
- 当前：
  - 主要是“是否被锁/是否来袭导弹”+简单距离档位。
  - RWR显示信息与BVR显示信息有重叠但缺统一威胁管理器。

### 3.4 电子对抗（ECM/Chaff/Flare）

- 现实：
  - 干扰效果取决于导引头类型、几何关系、时间窗和抗干扰能力。
- 当前：
  - 已有 `chaff/flare/ECM` 基础逻辑，但大多是近似“直接脱锁”或固定范围处理。

## 4. 重构建议（建议分阶段）

## 4.1 阶段 A：先做“统一数据层”，不改手感

目标：不动武器平衡前提下，把链路收束。

- 新增统一对象：
  - `SensorTrack`：目标ID、类型、方位、估计距离、速度估计、置信度、最后更新时间。
  - `ThreatTrack`：威胁级别（SEARCH/TRACK/MISSILE_ACTIVE）、来源武器、TTC估计。
- 新增统一服务：
  - `RadarService`：只负责扫描与轨迹维持。
  - `RwrService`：只负责威胁融合与告警级别。
  - `GuidanceService`：只负责导弹制导状态机。

收益：先解决“逻辑分散、重复判定、调试困难”。

## 4.2 阶段 B：重做导弹状态机（核心）

建议统一导弹制导阶段：

- `BOOST`：起飞段（刚体机动限制）
- `MIDCOURSE`：中段制导（可接收平台更新）
- `TERMINAL`：末段自导
- `MEMORY`：短时丢失记忆跟踪
- `LOST`：完全丢失

按导引头分支：

- SARH：`MIDCOURSE/TERMINAL`都要求“照射有效”。
- ARH：可在 `pitbullRange` 进入末段自导。
- ARM：目标类型改为“辐射源track”。

## 4.3 阶段 C：重构 RWR（感知与告警分离）

- 事件分级：
  - `SEARCH`
  - `TRACK`
  - `MISSILE_LAUNCH`
  - `MISSILE_ACTIVE`
- 每级独立音效节奏和显示样式（含去抖与优先队列）。
- RWR 不直接读“所有实体”，改读 `ThreatTrack`。

## 4.4 阶段 D：BVR 火控一体化

- 将 `MCH_RenderLeadCircle` 的目标锁定行为并入火控管理器。
- `PacketLockTargetBVR` 改为明确的“中段更新包”，仅发给相关导弹实例。
- 实现基础 TWS（track-while-scan）：
  - 可维护少量 track（例如 8）
  - 可指定主攻击目标（L&S）

## 9. 地面载具扫描面板动画调研（2026-04-18补充）

### 9.1 当前地面载具RWR位置与大小（代码实测口径）

当前地面载具（`MCH_EntityTank`）RWR在 `MCH_RenderRWR` 中渲染，使用以下基准参数：

- `RWR_SIZE = 160`
- `RWR_CENTER_X = 220`
- `RWR_CENTER_Y = 370`

实际绘制并非固定像素，而是按屏幕高度缩放：

- `sx = scaledHeight * (RWR_CENTER_X / 520)`
- `sy = scaledHeight * (RWR_CENTER_Y / 520)`
- `radius = scaledHeight * (RWR_SIZE / 520) / 2`

因此可视化参数可近似理解为：

- 中心X约为 `0.4231 * scaledHeight`
- 中心Y约为 `0.7115 * scaledHeight`
- 半径约为 `0.1538 * scaledHeight`

这属于“按屏幕高度缩放”的半自适应方案（不是完整宽高锚点布局）。

### 9.2 新扫描面板需求可实现性结论

你提出的方案可以直接落地，且与当前渲染链路兼容。可将新面板叠加在现RWR位置，后续再移除旧RWR底图。

新增开关要求：

- `EnableRadar=true` 时才启用该扫描面板。
- `EnableRadar=false` 时不渲染新面板（可继续保留旧RWR，或按后续重构策略隐藏）。
- 建议将其与现有 `EnableEntityRadar` 区分，避免语义混淆：  
  `EnableEntityRadar` 偏“雷达能力”，`EnableRadar` 偏“该新面板渲染开关”。

视觉规范（按需求）：

- 扇形/圆形边线：`#FFE400`，线宽 `1px`
- 扇形填充：`#FFE400`，透明度 `30%`
- 扫描线：`#FFE400`
- 命中点：`2x2 px`，`#FFE400`
- 命中点文字：显示对应 `NameOn*Radar`

### 9.3 扫描角度模式定义

1. `0 < ScanAngle <= 180`
   - 面板为朝上扇形。
   - 扫描线从最左扫到最右，再从右扫回左（往返为一个周期）。
   - 周期时长：`RadarScanTick`。

2. `180 < ScanAngle < 360`
   - 面板仍为朝上扇形。
   - 以扇心作为视觉中心更自然。
   - 扫描线仍用左右往返。

3. `ScanAngle = 360`
   - 面板为整圆。
   - 扫描线单向 `0 -> 360`，不回扫。
   - 一圈即一个周期：`RadarScanTick`。

### 9.4 0-180度模式的“中心偏移”几何规则

你的关键需求是：`0-180` 时不让扇心占据旧RWR中心，而是让“扇面上缘中点区域”更贴近旧中心。

可用如下偏移：

- 设半角 `a = ScanAngle / 2`
- 设扇半径为 `R`
- 扇面上缘中点距扇心沿主轴距离为 `R * cos(a)`

若旧RWR中心为 `C`，则可令新扇心为：

- `FanCenter = C + DownDir * (R * cos(a))`

这样上缘中点会落回 `C` 附近，视觉上符合“重点区域居中”的要求。

### 9.5 动画节奏建议

- 扫描参数驱动：
  - `RadarScanTick` 控制周期
  - `phase = (worldTime % RadarScanTick) / RadarScanTick`
- 非360模式：
  - `phase in [0, 0.5]` 左->右
  - `phase in (0.5, 1.0]` 右->左
- 360模式：
  - `theta = 360 * phase` 单向旋转

### 9.6 与概率扫描机制的衔接

可直接和“概率扫描+TTL保持”机制共用：

- 周期结束时执行一次目标命中判定
- 命中则写入 `contactCache[targetId] = holdTick`
- `ttl > 0` 期间绘制目标点与名称

这样既有“扫描动画感”，又不会引入复杂回波计算。

### 9.7 实施顺序（推荐）

1. 参数接入：在 `MCH_AircraftInfo` 新增 `EnableRadar`，默认 `false`，并支持配置解析。
2. 渲染门控：在 `MCH_RenderRWR` 开头增加 gate，只有 `EnableRadar=true` 才走新面板渲染。
3. 面板骨架：按当前地面RWR锚点先画静态扇形/圆形（边线+30%填充），暂不启用扫描线。
4. 动画接入：实现扫描线（`<=180` 往返、`180~360` 往返、`360` 单向旋转），周期使用 `RadarScanTick`。
5. 中心偏移：在 `0~180` 模式应用偏移公式 `FanCenter = C + DownDir * (R * cos(a))`，其余模式保持扇心居中。
6. 目标显示：接入命中点 `2x2` 与名称绘制，先做固定示例点验证布局，再接真实目标坐标映射。
7. 概率扫描：在扫描周期末执行命中判定，写入 `contactCache + TTL`，由缓存控制点位持续显示。

### 9.9 俯仰扫描参数补充定义

`RadarScanElevationDeg` 建议定义为“垂直扫描总扇区角”，范围 `0~180`：

- `0`：不进行俯仰扫描
- `180`：覆盖完整上下半球

新增两个开关用于满足“地面载具上视/战机全域”差异：

1. `RadarElevationReference`
   - `HORIZON`：按平飞水平面作为俯仰参考（推荐地面载具）
   - `AIRCRAFT`：按机体当前姿态作为俯仰参考（推荐战斗机）

2. `RadarElevationCoverage`
   - `UP_ONLY`：只扫描参考面的上半域（不下视）
   - `FULL`：扫描参考面的上下全域

典型组合建议：

- 地面载具：`RadarElevationReference=HORIZON` + `RadarElevationCoverage=UP_ONLY`
- 战斗机：`RadarElevationReference=AIRCRAFT` + `RadarElevationCoverage=FULL`

## 10. SRC/TWS 跟踪模式调研与实施方案（新增）

### 10.1 目标

将当前“仅扫描显示”扩展为“搜索 + 选择 + 跟踪 + 火控联动”体系，支持：

- `RadarSearchType=SRC|TWS`（默认 `SRC`）
- 选择目标键（建议 `CAP`）
- 右键进入/退出跟踪
- 跟踪角限制（水平/俯仰）
- 跟踪状态下与 BVR/预瞄圈联动

### 10.2 建议新增参数

- `RadarSearchType=SRC|TWS|GMTI_SRC|GMTI_TWS`（默认 `SRC`）
- `RadarTrackAzimuthDeg`（跟踪最大水平角）
- `RadarTrackElevationDeg`（跟踪最大俯仰角）
- `RadarRetargetCooldownTick`（主动切目标后短时不可重选）
- （可选）`RadarTrackKeepWithoutScanTick`（脱扫短时记忆保持）
- `RadarMaxScanAltitude`（默认 `25`，仅 GMTI 生效）

GMTI 目标定义（本次确认）：

- `GMTI_SRC/GMTI_TWS` 只做对地搜索与显示。
- “地面目标”范围包括低空在内的所有目标（不再只限贴地目标）。
- GMTI 模式不使用 `RadarMinScanAltitude`，改用 `RadarMaxScanAltitude` 做高度上限。
- `RadarMinScanAltitude` 与 `RadarMaxScanAltitude` 均按离地高度（AGL）定义。

约束建议：

- `RadarTrackAzimuthDeg <= RadarScanAzimuthDeg`
- `RadarTrackElevationDeg <= RadarScanElevationDeg`

### 10.3 状态机建议

建议新增统一雷达目标状态：

- `SCAN_CONTACT`：扫描命中/TTL显示
- `SELECTED`：被选择（红色点/红色名字/BVR框红色）
- `TRACKING`：右键进入雷达跟踪
- `LOST`：脱锁后回到扫描态

关键状态字段：

- `selectedTargetId`
- `trackingTargetId`
- `lastManualDroppedTargetId`
- `manualDropCooldownTick`

### 10.4 行为规则（按需求映射）

1. `CAP` 选择目标
   - 仅在 `RadarContactHoldTick` 有效目标中选择。
   - 选择顺序按“前向角度优先 + 距离优先”。
   - 再次按 `CAP` 切到下一个目标。
   - 因手动切换放弃的目标，短时间内不参与重选。

2. 右键锁定跟踪
   - 仅当目标在跟踪角范围内（`RadarTrackAzimuthDeg/RadarTrackElevationDeg`）可进入跟踪。
   - 跟踪目标在雷达界面与 BVR 框显示红色。

3. `SRC` 模式
   - 搜索与跟踪互斥。
   - 跟踪时只显示被跟踪目标。
   - 雷达中心到目标连线为实线。
   - 跟踪目标不受 `RadarContactHoldTick` 到期直接消失影响（由脱锁条件驱动）。

4. `TWS` 模式
   - 可边搜索边跟踪。
   - 其它搜索目标继续显示。
   - 连线为虚线。
   - 可通过选择键或右键主动脱锁。

5. 脱锁条件（统一）
   - 玩家右键取消。
   - 目标释放箔条。
   - 超出 `RadarTrackAzimuthDeg` 或 `RadarTrackElevationDeg`。
   - （SRC/TWS）目标低于 `RadarMinScanAltitude`（AGL）。

### 10.5 与火控预瞄圈/ ahead 联动

当前建议：

- 删除“CAP 直接触发火控预瞄圈”的旧路径。
- 改为“仅在 `TRACKING` 状态下”启用预瞄圈与 ahead 求解。
- 即火控目标 ID 来源统一为 `trackingTargetId`。

收益：

- 雷达态势与火控态势一致，避免“看似锁定但雷达未跟踪”的行为割裂。

### 10.6 实施步骤（推荐）

#### 阶段 A：参数与基础状态

1. 在 `MCH_AircraftInfo` 增加 `RadarSearchType`、`RadarTrackAzimuthDeg`、`RadarTrackElevationDeg`、`RadarRetargetCooldownTick`、`RadarMaxScanAltitude`。
2. 在 `MCH_RenderRWR` 增加 `selectedTargetId/trackingTargetId` 状态容器（按载机实体ID索引）。
3. 加参数有效性钳制与日志输出（调试看当前生效值）。

#### 阶段 B：选择目标

1. 在客户端按键层接入 `CAP`（或绑定到可配置 key）。
2. 从当前 `contactCache` 里按“前向角 + 距离”排序选目标。
3. 渲染上把选中目标改红（点、名字、BVR框）。
4. 实现“手动放弃目标冷却”。

#### 阶段 C：跟踪模式（先 SRC）

1. 右键进入/退出 `TRACKING`。
2. 判断是否在跟踪角范围内，不在则拒绝进入/立即脱锁。
3. `SRC` 跟踪时只显示跟踪目标，其它目标隐藏。
4. 中心到目标画实线。

#### 阶段 D：扩展 TWS

1. `TWS` 下保留搜索与缓存显示，不屏蔽其它目标。
2. 跟踪连线改虚线。
3. 支持选择键脱锁与切换目标。

#### 阶段 E：火控联动

1. `MCH_RenderLeadCircle`、`ahead` 读取雷达 `trackingTargetId`。
2. 无 `trackingTargetId` 时关闭预瞄圈和 ahead 计算。
3. 清理旧 `CAP` 火控锁定路径，避免双源冲突。

#### 阶段 F：稳定化与验收

1. 用 `radardebug` 增加跟踪态日志（进入/退出原因）。
2. 补充异常保护（目标消失、跨维度、实体ID复用）。
3. 做两组平衡预设：
   - 地面载具（SRC、上视）
   - 战斗机（TWS、全域）
