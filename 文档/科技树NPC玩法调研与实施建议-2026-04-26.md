# 科技树 NPC 玩法调研与实施建议（2026-04-26）

## 1. 目标与范围
- 参考战争雷霆科技树玩法，新增可配置的 NPC 交互系统。
- NPC 默认使用原版史蒂夫模型与贴图，同时支持在配置中切换 `mcheli/textures/skins` 下的皮肤。
- 引入三种货币：银狮（SL）、金鹰（GE）、研发点（RP）。
- 规则目标：
- RP 用于研发载具节点。
- 研发可配置前置节点依赖。
- 同一载具研发完成后永久生效，不需要重复研发。
- SL 用于购买已研发载具。
- GE 作为高级货币，可用于购买特定载具，或兑换 SL/RP。

## 2. 现状复用评估
- 已有可复用能力：
- `MCH_EntityGunner`、`MCH_RenderGunner`（已使用 `ModelBiped`），适合参考但不建议直接承载新系统业务。
- 配置化加载体系已成熟（如 gunner/blocks/weapon/vehicle 等 info manager）。
- GUI 通用入口已具备（`MCH_GuiCommonHandler` 可扩展新 GUIID）。
- 服务端 Tick 统一入口已具备（可挂村庄刷新调度器）。
- 结论：
- 该需求可落地，建议按“新实体 + 新配置 + 新存档 + 新交易协议”独立实现，避免污染现有 gunner 战斗 AI。

## 3. 推荐总体架构
- 新增实体：
- `MCH_EntityTechNpc`：专职商店/科技树交互，不参与 gunner 战斗逻辑。
- 新增渲染：
- `MCH_RenderTechNpc`：默认 `minecraft:textures/entity/steve.png`。
- 支持配置皮肤路径，例如 `mcheli:textures/skins/<name>.png`。
- 新增系统模块：
- `MCH_EconomyManager`：货币账户、增减逻辑、兑换规则、日志。
- `MCH_TechTreeManager`：节点定义、依赖校验（DAG）、解锁状态判定。
- `MCH_TechNpcSpawnManager`：村庄刷新调度、上限与冷却控制。
- 新增网络协议：
- 客户端只发“请求操作”（研发/购买/兑换）。
- 服务端执行校验并写入存档，再回包刷新 UI。

## 4. 数据与存档设计
- 玩家经济数据（按 UUID）：
- `sl`、`ge`、`rp`。
- `researchedNodes`（已研发节点集合）。
- `purchasedCountByNode`（节点购买次数，可选）。
- 世界级数据：
- NPC 刷新冷却、村庄配额、维度上限。
- 存储建议：
- 使用 `world/data` 下独立 NBT 文件（例如 `mcheli_tech_economy.dat`）。
- 原则：服务端权威，客户端不持久化，不信任客户端余额。

## 5. 配置文件方案（建议）
- `assets/mcheli/npc_profiles/*.txt`
- `DisplayName`：NPC 显示名。
- `Skin`：皮肤路径（默认 steve）。
- `VillageWeight`：村庄刷新权重。
- `SpawnBiomeTags`：可刷新生物群系标签。
- `OpenGuiId`：打开的 UI 类型。
- `assets/mcheli/tech_tree/*.txt`
- `NodeId`：科技树节点 ID（唯一）。
- `VehicleType`：`plane|heli|tank|vehicle`。
- `VehicleName`：载具配置名。
- `RPCost`、`SLCost`、`GEPrice(optional)`。
- `Prerequisite`：前置节点，`|` 分隔。
- `Premium`：是否高级载具（可 GE 直购）。
- `Nation/Line/Tier(optional)`：用于 UI 分栏展示。
- `assets/mcheli/economy/economy.txt`
- `Exchange_GE_to_SL`、`Exchange_GE_to_RP`。
- `DailyReward(optional)`。
- `MaxBalance(optional)`。
- `VillageSpawnMinIntervalTick`、`VillageSpawnCapPerVillage`。

## 6. 业务规则建议
- 研发规则：
- 需要 `RP >= RPCost`。
- 所有前置节点均已研发。
- 已研发节点不可重复扣费研发。
- 购买规则：
- 仅当节点已研发时可 SL 购买。
- 扣费后发放对应载具（或发放“可提取凭证”）。
- 高级规则：
- `Premium=true` 节点允许 GE 购买。
- GE 可按配置比率兑换 SL/RP。
- 安全规则：
- 所有扣费与发放都在服务端执行与记账。
- 任意失败必须回滚并回传原因码。

## 7. 村庄随机刷新建议
- 先做保守策略，避免性能抖动：
- 每隔固定 tick 低频扫描可加载区块内村庄。
- 每村庄设置 NPC 数量上限、刷新冷却、玩家距离门槛。
- 仅在白天或可配置时段刷新（可选）。
- 失败重试采用退避冷却，避免高频反复尝试。
- 防刷建议：
- NPC 交易后进入短冷却。
- 可配置“每玩家每日交易上限”（可选）。

## 8. 分阶段实施路线
- 阶段 A（MVP，优先）：
- 命令刷出 Tech NPC。
- 完成三货币账户、科技树节点研发、购买、GE 兑换。
- 基础 GUI（列表+详情+按钮）与服务端校验回包。
- 阶段 B：
- 接入村庄随机刷新与配额控制。
- 接入皮肤配置与 profile 多样化。
- 阶段 C：
- 科技树 UI 分国家/分支/等级。
- 活动系数与经济平衡参数（赛季或服务器活动）。

## 9. 风险与规避
- 风险：直接复用 `MCH_EntityGunner` 会引入驾驶/战斗逻辑耦合。
- 规避：独立 `MCH_EntityTechNpc`，仅复用模型渲染结构。
- 风险：客户端伪造请求导致刷币/白嫖。
- 规避：全链路服务端权威校验，客户端只显示。
- 风险：村庄扫描频率过高影响 TPS。
- 规避：低频调度 + 配额 + 冷却 + 失败退避。
- 风险：科技树配置循环依赖。
- 规避：加载时做 DAG 检测，异常节点禁用并打印错误日志。

## 10. 最小可用字段清单（先实现）
- 玩家数据：`SL`、`GE`、`RP`、`researchedNodes`。
- 节点字段：`NodeId`、`VehicleType`、`VehicleName`、`RPCost`、`SLCost`、`Prerequisite`。
- 经济字段：`Exchange_GE_to_SL`、`Exchange_GE_to_RP`。
- NPC 字段：`DisplayName`、`Skin`。

## 11. 推荐下一步
- 先落地阶段 A（MVP）并完成两套示例配置：
- 新手线：3~5 个节点，验证前置依赖与扣费链路。
- 高级线：包含 `Premium` 节点，验证 GE 购买与兑换。
- 待 MVP 稳定后，再开启村庄随机刷新，便于定位问题与调平经济。
