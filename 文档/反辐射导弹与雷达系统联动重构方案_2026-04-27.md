# 反辐射导弹与雷达系统联动重构方案（2026-04-27）

## 1. 调研结论（当前机制）

### 1.1 配置与开关
- 武器配置存在 `AntiRadiationMissile` 字段，映射到 `MCH_WeaponInfo.antiRadiationMissile`。
- 当前仓库内未检索到 `AntiRadiationMissile=true` 的资源配置，说明该机制尚未被实装启用。

### 1.2 现有 ARM 判定逻辑
- ARM 逻辑主要出现在导弹扫描目标阶段：
  - 当 `getInfo().antiRadiationMissile` 为真时，仅允许锁定"有 RWR 的载具"，并排除"ECM type=2 且正在干扰"的目标。
  - 逻辑位于 `MCH_EntityBaseBullet.scanForTargets()` 的 AT 导弹扫描分支。
- ARM 未使用 `MCH_RWRThreatManager` 的雷达跟踪/威胁事件作为目标输入，仅依赖目标自身属性（`hasRWR`、`ecmJammerType`）和即时状态（`isECMJammerUsing`）。

### 1.3 与雷达系统现状关系
- 雷达系统已具备完整威胁链：
  - 服务端记录发射机跟踪：`reportRadarTracking` / `reportGunnerTracking`
  - 威胁归一化与下发：`emitScanThreatForEmitter`、`emitLockThreatForEmitter`、`emitMissileThreats`、`dispatchThreatTables`
  - 可判断"某发射机是否正在跟踪某目标"：`isEmitterTrackingTarget(...)`
- 但 ARM 没有消费上述"发射机行为"数据，导致"反辐射"语义和雷达系统脱节。

### 1.4 数据链与 UI 现状
- 雷达弹的数据链逻辑显式排除了 ARM（`antiRadiationMissile` 下不走数据链发射/更新逻辑）。
- RWR 雷达导弹覆盖层渲染也显式排除 ARM。
- 这意味着 ARM 目前既不是"雷达弹数据链体系"的一员，也不是"雷达发射源寻的体系"的一员，处于功能孤岛状态。

## 2. 现状问题清单

1. **语义偏差**：当前更像"特定类型地面目标过滤导弹"，不是"反雷达发射源导弹"。
2. **目标源错误**：ARM 应该追踪"发射机（Emitter）"，当前追踪"被筛选后的目标实体（通常是载具）"。
3. **缺少时间连续性**：没有"最后辐射源记忆窗口"，辐射中断后行为突兀。
4. **ECM 语义粗糙**：仅特殊判断 `ecmJammerType==2`，未统一并入雷达威胁/反制状态。
5. **可调参数不足**：缺少 ARM 特有参数（被动搜寻角、记忆时长、最小威胁等级、抗干扰门限等）。
6. **未接入实战配置**：资源文件无启用项，无法通过内容侧验证。

## 3. 重构目标

1. ARM 以"雷达辐射源"为主目标，而非普通实体过滤目标。
2. ARM 与 `MCH_RWRThreatManager` 打通，复用现有威胁数据。
3. 在辐射中断时具备"惯导 + 最后辐射源记忆"行为。
4. ECM/箔条对 ARM 的影响可配置且统一，其中 ECM 目标在 ARM 评分中为最高优先级。
5. 与现有雷达弹、RWR UI、数据链机制兼容，避免破坏存量武器行为。
6. 增加雷达静默（关雷达）战术行为，与 ARM 形成攻防博弈闭环。

## 4. 总体设计（建议）

### 4.1 新增"辐射源候选层"（核心）

在 `MCH_RWRThreatManager` 增加服务端查询接口（只读）：
- `collectArmEmitterCandidates(MCH_EntityAircraft seekerPlatform, long now, ArmQueryOptions options)`
- 返回 `List<ArmEmitterCandidate>`

`ArmEmitterCandidate` 建议字段：
- `emitterEntityId`
- `emitterKind`（机载雷达/地面雷达）
- `threatMode`（SEARCH/STT/MSL）
- `distanceMeters`
- `bearingDeg`
- `confidence`
- `lastSeenTick`
- `sourceName`

候选来源优先级（高到低）：
1. 正在开启 ECM 的敌方目标（Home-On-Jam，最高权重）
2. 正在 STT 跟踪我方平台的发射机
3. 对我方产生稳定 SEARCH 的发射机
4. 与我方同扇区、同高度窗的其他雷达发射机（可选）

过滤规则（必须）：
- 屏蔽同阵营目标（含玩家载具与 gunner 防空载具）的雷达/ECM辐射，不可作为 ARM 候选。
- 目标必须满足基础几何条件（距离、FOV、高度窗），否则不入池。

### 4.2 ARM 导弹寻的状态机（替代当前 if 过滤）

新增 `ArmGuidanceState`：
- `SEEKING_EMITTER`：搜索辐射源并建立锁定
- `HOMING`：持续导引至发射机位置（可预测）
- `MEMORY`：辐射丢失后按最后解算位置飞行（`memoryTick`）
- `TERMINAL`：末制导（近炸/碰炸）
- `LOST`：丢失后自毁或直飞（配置）

状态切换关键：
- `SEEKING_EMITTER -> HOMING`：候选评分达阈值
- `HOMING -> MEMORY`：辐射中断（超 `armEmitterLostGraceTick`）
- `MEMORY -> HOMING`：重新捕获同一或更高评分发射机
- `MEMORY -> LOST`：超 `armMemoryTimeTick`

### 4.3 评分模型（可调）

候选评分建议：
- `score = wMode * modeScore + wRange * rangeScore + wAspect * aspectScore + wConf * confidence`

建议默认：
- `modeScore`: `ECM=1.2`, `MSL=1.0`, `STT=0.9`, `TRACK=0.6`, `SEARCH=0.4`
- `rangeScore`: 随距离线性衰减
- `aspectScore`: 超出导引头视场角强惩罚
- `confidence`: 直接来自威胁系统，参与加权
- `manualLockBoost`: 窄频带手动锁定目标附加权重（建议 +0.5）

### 4.4 ECM 与反制协同

统一 ECM 影响入口，不再仅判断 `ecmJammerType==2`：
- ECM 开启目标直接进入 ARM 高优先级候选（HOJ目标）。
- 对非 HOJ 场景保留 `confidence` 衰减与误差注入（软对抗）。
- 对特定 ARM 型号允许"抗干扰计时"参数（类似 `antiFlareCount` 思路）。

### 4.6 雷达开关与静默行为（新增）

新增雷达总开关（默认绑定 `~` 键）：
- 按下后：关闭雷达扫描与锁定；再次按下重新开启。
- 关闭雷达期间：不产生新的 `SEARCH/STT` 辐射事件。
- 关闭雷达期间：`AddPartTurretRotation` 关联旋转部件停止转动（视觉反馈）。
- 建议增加开关冷却（如 40~100 tick）防止抖动开关。

### 4.7 ARM 宽/窄频带双模式（新增）

模式切换：
- 使用"切换武器模式"按键切换 ARM 频带模式（不新增独立按键）。
- 武器名后缀显示当前模式：
  - 中文环境：`[宽频]` / `[窄频]`
  - 非中文环境：`[WB]` / `[NB]`（WideBand / NarrowBand）

宽频带模式（默认）：
- 发射后按"辐射源候选评分 + 状态机"自动寻的。
- 无需预选目标，可盲发后自寻优先辐射源。

窄频带模式（手动高优）：
- 不依赖本机雷达数据链；无目标时禁止发射。
- 一旦被对手雷达扫描到，即在专用 ARM 目标层渲染 RWR BVR 框。
- 可用 CAP 切换目标；右键执行锁定。
- 被手动锁定目标获得最高优先级（高于普通评分目标）。
- 该目标框：
  - 使用 `NameOnRWR` 显示目标名；
  - 常规颜色为 `FEE400`；
  - 不显示在雷达 GUI 上；
  - 可显示在 RWR 面板与 ARM 专用目标层。
- 当同载具有"雷达锁定目标"与"ARM锁定目标"同时存在时，ARM 锁定优先级最高。
- ARM BVR 框只在"当前选中武器为 ARM"时显示，切换到非 ARM 武器后不显示。

ARM BVR 框驻留与刷新规则（新增）：
- 基础驻留时间：`armBvrBoxTtlTick = max(15, RadarContactHoldTick / 2)`。
- 触发条件采用"扫描动作触发"而不是"扫描命中触发"，以保证隐身目标场景下反辐射任务可执行。
- 敌雷达处于持续锁定（STT）时，ARM BVR 框持续渲染（持续刷新TTL）。
- 同一 `emitterId` 建议增加最小刷新间隔（`2~4 tick`），避免高频刷屏导致闪烁。
- 显示分级建议：`SCAN` 使用常规亮度，`STT` 使用增强亮度/描边。

### 4.8 ARM 巡航弹道（附加任务）

新增可配置弹道类型：`armCruiseTrajectory`（默认关闭）。

行为规则：
- 当 `armCruiseTrajectory=true` 且目标距离大于最小启动距离时，导弹进入"巡航段"：
  - 自动改为平飞巡航（保持高度，不做俯仰追踪）；
  - 仅进行 `yaw` 偏航修正，朝目标水平投影方向飞行。
- 当导弹进入"以目标为中心，半径 50、高 1024 的圆柱区域"后，切入"末段俯冲/直冲"：
  - 恢复常规弹道导引，向目标点冲击。
- 当目标距离小于等于最小启动距离时，不进入巡航段，直接采用常规弹道。

建议默认参数：
- `armCruiseEnable=false`
- `armCruiseStartDistance=150`（米）
- `armCruiseTerminalRadius=50`（米）
- `armCruiseTerminalHeight=1024`（米）

配置层要求：
- 在武器配置文件可独立开启/关闭该弹道；
- 不开启时完全保持现有导引行为。

### 4.5 数据结构与参数扩展

建议在 `MCH_WeaponInfo` 新增 ARM 参数（均有默认值，保持兼容）：
- `armEnable`（兼容 `antiRadiationMissile`，可复用原字段）
- `armSeekerFovDeg`（默认 60）
- `armMaxLockRange`（默认沿用 `maxLockOnRange`）
- `armMemoryTimeTick`（默认 40）
- `armEmitterLostGraceTick`（默认 10）
- `armMinThreatMode`（默认 `SEARCH`）
- `armPreferSTT`（默认 true）
- `armEcmResistance`（0~1，默认 0.3）

配置解析可继续放在 `MCH_WeaponInfo.loadItemData(...)` 中，旧配置不填即走默认。

## 5. 代码落点与改造建议

## 6. 兼容性策略

1. `antiRadiationMissile=false` 的武器完全不变。
2. ARM 新逻辑通过 `armUseEmitterPipeline`（默认 true）控制，可随时回退。
3. 保留旧扫描逻辑作为 fallback，确保旧地图/旧内容包可运行。
4. 不改网络包格式的前提下先落地服务端逻辑；如需客户端可视化再增量扩展包体。

## 7. 验收标准（建议）

### 7.1 功能验收
- ARM 可优先命中"正在开启 ECM 的敌方目标"，其后才是 STT/SEARCH 发射机。
- 发射机短时关机/中断后，导弹可进入 MEMORY 而非立即失控。
- `~` 雷达开关可正常切换扫描/锁定，并在关闭时停止 `AddPartTurretRotation` 相关转动。
- 窄频带模式无目标不可发射，可通过 CAP 切换 + 右键锁定后发射。
- 窄频带 RWR 框显示 `NameOnRWR`，颜色为 `FEE400`，且不进入雷达 GUI。
- ARM BVR 框仅在当前选中 ARM 武器时显示。
- ARM BVR 框驻留时间符合 `max(15, RadarContactHoldTick / 2)`，且按"扫描动作"刷新而非"扫描命中"刷新。
- 敌雷达持续 STT 时，ARM BVR 框持续显示；停止辐射后按 TTL 衰减消失。
- 当 `armCruiseEnable=true` 且目标距离大于 `armCruiseStartDistance` 时，导弹先平飞巡航，仅做 yaw 修正。
- 导弹进入"终端圆柱（R=50,H=1024）"后切换常规末段导引；近距离目标（<=150）直接走常规弹道。

### 7.2 回归验收
- 主动/半主动/被动雷达弹现有数据链逻辑无回归。
- RWR 威胁排序逻辑无回归（MSL > STT > TRACK > SEARCH）。
- 非 ARM 的 AT/AA 导弹锁定逻辑无行为变化。

### 7.3 性能验收
- 每 tick ARM 候选查询不引入明显卡顿；
- 候选数量和评分计算有上限（如每发导弹最多评估 N=12 个候选）。

# 扩展调研：雷达与数据链系统（完整报告）

## 1. 雷达系统架构总览

雷达系统由三层构成：

### 1.1 配置层（MCH_AircraftInfo.java: L155-L260）

每架载具通过配置文件定义雷达参数：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enableRadar` | boolean | false | 是否启用新雷达扫描动画面板 |
| `radarScanAzimuthDeg` | float | 120 | 水平扫描扇区总角度 |
| `radarScanElevationDeg` | float | 40 | 俯仰扫描扇区总角度 |
| `radarScanTick` | int | 12 | 扫描周期（tick） |
| `radarDetectChanceBase` | float | 0.75 | 基础命中概率 |
| `radarGainNearFactor` | float | 1.5 | 距离增益近端系数 |
| `radarGainFarFactor` | float | 0.5 | 距离增益远端系数 |
| `radarContactHoldTick` | int | 40 | 目标显示保持时长（tick） |
| `radarMaxTargetRange` | float | 3000 | 最大显示距离（米） |
| `radarMinScanAltitude` | float | 10 | 最小扫描高度（AGL） |
| `radarMaxScanAltitude` | float | 25 | 最大扫描高度（用于GMTI模式） |
| `radarSearchType` | String | "SRC" | 搜索模式：SRC/TWS/GMTI_SRC/GMTI_TWS/MULTI_SRC/MULTI_TWS |
| `radarTrackAzimuthDeg` | float | 90 | 跟踪最大水平角度 |
| `radarTrackElevationDeg` | float | 45 | 跟踪最大俯仰角度 |
| `radarFollowTurretYaw` | boolean | false | 雷达方向是否跟随炮塔（仅坦克） |
| `radarElevationReference` | String | "HORIZON" | 俯仰参考系：HORIZON/AIRCRAFT |
| `radarElevationCoverage` | String | "UP_ONLY" | 覆盖模式：UP_ONLY/FULL |
| `radarPanelFillAlpha` | float | 0.30 | 面板填充透明度 |
| `enableBVR` | boolean | false | 是否允许BVR索敌/火控显示 |
| `radarRetargetCooldownTick` | int | 40 | 放弃目标后禁止重选冷却 |
| `radarRcsFrontFactor` | float | 1.0 | RCS前向系数 |
| `radarRcsSideFactor` | float | 1.0 | RCS侧向系数 |
| `radarRcsRearFactor` | float | 1.0 | RCS后向系数 |
| `radarRcsTimeFactor` | float | 1.0 | RCS保持时间系数 |

搜索模式定义：
- **SRC**（Single-Radar Contact）：单目标跟踪模式，需锁定后进入 STT
- **TWS**（Track-While-Scan）：边扫边跟，可保持 selected + tracking 分离
- **GMTI_SRC/GMTI_TWS**：地面动目标指示模式，过滤高空目标，聚焦低空（默认 `radarMaxScanAltitude=25` 米）
- **MULTI_SRC/MULTI_TWS**：多模式（同时检测空中+地面目标）

### 1.2 运行时开关层（MCH_EntityAircraft.java: L6682-L6694）

```java
public boolean isRadarEnabledRuntime()        // 雷达运行时是否开机
public void setRadarEnabledRuntime(boolean)   // 设置开机/关机
```

#### 三类雷达导弹的数据链行为

**PassiveRadar + 数据链**：
- 发射后数据链为唯一引导来源
- 机载雷达脱锁 → 导弹立即失联（`dlRelayLostTick > DL_RELAY_LOST_GRACE_TICK` 后清除 relay 标志）
- 失联后不能自主重捕获（`scanForTargets()` 被屏蔽）

**SemiActiveRadar + 数据链**：
- 与 PassiveRadar 相同，DL 下封禁半主动"持续照射"链路
- 数据链丢失后保留运动学惯性（grace period 内用最后已知位置+速度预测）

**ActiveRadar + 数据链（并行策略）**：
- 主动雷达与数据链并行，主动雷达优先
- 未捕获前（`isDataLinkActiveRadarDelayPhase()`）：可用数据链中继
- 捕获后（`isActiveRadarCaptured()`）：停止数据链，切换到主动自导
- 数据链丢失但主动已捕获 → 仍可继续
- 双重丢失 → 失联

# 扩展调研：反辐射导弹巡航弹道（完整报告）

## 1. 参数定义

已在 `MCH_WeaponInfo.java` 中完整实现：

| 参数 | 类型 | 默认值 | 配置项名 |
|------|------|--------|---------|
| `armCruiseEnable` | boolean | false | `ArmCruiseEnable` |
| `armCruiseStartDistance` | double | 150.0 | `ArmCruiseStartDistance` |
| `armCruiseTerminalRadius` | double | 50.0 | `ArmCruiseTerminalRadius` |
| `armCruiseTerminalHeight` | double | 1024.0 | `ArmCruiseTerminalHeight` |

## 2. 巡航判定逻辑

在 `MCH_EntityAAMissile.shouldUseArmCruise()` 和 `MCH_EntityATMissile.shouldUseArmCruise()` 中逻辑一致：

```java
private boolean shouldUseArmCruise(double tx, double ty, double tz) {
    if (!getInfo().armCruiseEnable) return false;           // 开关关闭 → 不巡航
    
    double dx = tx - this.posX;
    double dy = ty - this.posY;
    double dz = tz - this.posZ;
    double dist = Math.sqrt(dx*dx + dy*dy + dz*dz);
    if (dist <= getInfo().armCruiseStartDistance) return false;  // 太近 → 不巡航
    
    double horizontal = Math.sqrt(dx*dx + dz*dz);
    // 已在终端圆柱内（R=50, H=1024）→ 不巡航
    if (horizontal <= getInfo().armCruiseTerminalRadius && Math.abs(dy) <= getInfo().armCruiseTerminalHeight)
        return false;
    
    return true;  // 其他情况 → 巡航
}
```

三段判定：

```
         巡航段                 终端段
    ──────────────────────────────────────►
    ↑                    ↑
    dist > startDist    进入圆柱(R=50, H=1024)
    (默认150米)          → 切换常规导引
    
    巡航段行为：
    - 调用 guidanceToPos(tx, this.posY, tz)
    - 保持当前高度（posY 不变）
    - 仅水平偏航修正
    
    终端段行为：
    - 调用 guidanceToPos(tx, ty, tz)
    - 全三维导引，可俯冲
```

## 3. 导引入口

`guideArmToPosition()` 是巡航/终端切换的唯一入口：

```java
private void guideArmToPosition(double tx, double ty, double tz) {
    if (shouldUseArmCruise(tx, ty, tz)) {
        guidanceToPos(tx, this.posY, tz);  // 巡航段：保持高度
    } else {
        guidanceToPos(tx, ty, tz);          // 终端段：全三维
    }
}
```

- 在 `onUpdateArmGuidance()` 的 HOMING 和 MEMORY 阶段都调用 `guideArmToPosition()`
- 巡航段中导弹仍然在 HOMING 状态，只是导引目标点的 Y 被锁定为当前高度
- `guidanceToPos()` 内部有最大转向角限制（`getCurrentMaxDegreeOfMissile()`）和转向因子平滑

## 4. 巡航弹道的战术意义

| 场景 | 巡航效果 |
|------|---------|
| 远距离目标（>150m） | 导弹先平飞，不暴露弹道弧顶，降低被拦截概率 |
| 近距离目标（≤150m） | 直接俯冲，不巡航，保证反应时间 |
| 已进入终端圆柱 | 全速俯冲/直冲，提高末段命中率 |
| 高差大的目标 | 巡航段保持高度，到目标头顶再俯冲，实现"高抛-俯冲"弹道 |

## 5. 参数调优建议

| 场景调整 | 改什么 |
|---------|--------|
| 想提高巡航段距离 | 增大 `armCruiseStartDistance`（默认150 → 300） |
| 想提前转入俯冲 | 增大 `armCruiseTerminalRadius`（默认50 → 100） |
| 想降低巡航高度（低空突防） | 不涉及参数，巡航段自动保持发射高度 |
| 想让导弹更早进入末段 | 减小 `armCruiseStartDistance` 或增大 `armCruiseTerminalRadius` |

# 追加改动记录（2026-04-30）

## 改动 1：HOJ 追踪精度惩罚

**提出时间**：2026-04-30，用户规划的第一条改动。

**要求**：
- 启用 ECM 的目标仍然是 ARM 最高优先级（HOJ 权重不变）。
- 但当 ARM 导弹追踪 ECM 开启的目标时，导引过程增加 **7 米随机圆概率误差（CEP）**。
- 具体表现：每帧计算制导向量时，在目标位置的水平面上叠加一个半径 7 米的二维随机偏移，偏移方向均匀随机，使导弹落点呈现以真实目标为中心的圆形散布。

**实现思路**：
- 修改 `MCH_EntityBaseBullet.scanForTargets()` 中 ARM 分支：在选出 `closestArmTarget` 后，若该目标 `isECMJammerUsing()` 为真，则在导弹实体上标记一个 `armHojCepActive = true`。
- 修改 `MCH_EntityAAMissile.onUpdateArmGuidance()` / `MCH_EntityATMissile` 对应方法：在 `armGuidanceState == HOMING` 且 `armHojCepActive` 时，对传入 `guideArmToPosition()` 的目标坐标在水平面上叠加随机偏移。
- 偏移生成：每 tick 重新采样 `xOffset = rand(-7,7), zOffset = rand(-7,7)`，叠加到 `targetEntity.posX / targetEntity.posZ` 上。
- 建议偏移更新频率：每 5~10 tick 重新采样一次，避免每帧抖动过大导致导弹蛇行。
- ECM 关闭后应立即清除 `armHojCepActive` 标志并恢复精确导引。
