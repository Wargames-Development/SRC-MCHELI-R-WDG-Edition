# 军事基地结构生成方案调研（1.7.10）

## 1. 目标

- 在生存模式世界中，按条件（例如平原地形）生成军事基地结构。
- 军事基地内部放置“载具生成器方块”，用于持续补充载具和炮手。
- 支持后续扩展为多模板随机、阵营基地差异化、战利品和守军逻辑。

## 2. 结论：是否必须使用 schem

- `schem/schematic` 不是必须，但在 1.7.10 场景下非常推荐。
- 不使用模板也能做（纯 Java 硬编码摆方块），但开发和维护成本高，不适合复杂基地。
- 推荐采用“模板文件 + 规则配置 + 世界生成器代码”的三层方案。

## 3. 同类 Mod 常见做法

- 纯代码结构生成：每个结构由 Java 手动摆放方块，控制强但维护困难。
- 模板驱动生成：结构本体放在模板文件中，代码只负责“何时、何地、如何旋转放置”。
- 模板池随机：同类型结构准备多份模板，按权重随机，提高重复游玩体验。
- 二次后处理：结构落地后再执行刷箱子、刷守军、放功能方块等逻辑。

## 4. 推荐落地架构（适配当前项目）

### 4.1 文件与资源

- `src/main/resources/assets/mcheli/structures/schems/*.schem`
  - 军事基地结构模板文件（可多个，编辑器导出源文件）。
- `src/main/resources/assets/mcheli/structures/*.txt`
  - 单结构定义（文件名即结构ID，记录模板路径、尺寸、锚点、旋转策略、地基策略、标记替换规则）。
- `src/main/resources/assets/mcheli/structure_rules/*.txt`
  - 生成规则（生物群系、概率、间距、高度、地形限制）。
- `src/main/resources/assets/mcheli/structure_pools/*.txt`
  - 模板池及权重（同类基地多模板随机）。
- `src/main/resources/assets/mcheli/blocks/*.txt`
  - 生成器方块参数（你已在用），模板中放置对应方块。

### 4.2 代码入口

- `MCH_WorldStructureGenerator`（实现 `IWorldGenerator`）
  - 在区块生成流程中按规则尝试生成基地。
- `MCH_StructureTemplateLoader`
  - 读取模板文件与模板池配置。
- `MCH_StructurePlacer`
  - 执行旋转、落地、地基处理、边界检查。
- `MCH_StructurePostProcessor`
  - 结构落地后二次处理：替换方块、设置方块状态、放置箱子/守军点。

## 5. 生成流程（建议）

1. 区块触发时读取当前生物群系，仅允许白名单（例如 `plains`）。
2. 按稀有度与间距规则决定是否尝试生成。
3. 选择模板池中的一份基地模板（支持权重随机）。
4. 选旋转方向（0/90/180/270）并计算包围盒。
5. 做选址校验（坡度、地表高度、可用空间、液体检查）。
6. 放置模板方块。
7. 执行后处理（例如设置基地内载具生成器方块参数或替换标记块）。

## 6. 与“载具生成器方块”的联动方案

- 基地模板中直接放置你配置过的生成器方块。
- 生成器继续使用现有 `blocks/*.txt` 参数驱动：
  - 载具池随机；
  - 普通炮手/阵营炮手；
  - 冷却与休眠贴图；
  - 等待“本次生成载具被摧毁后再进入冷却”。
- 可按基地类型放多个生成器点位，分别负责不同阵营或不同载具池。

## 7. 关键规则建议

- 生物群系限制：先只开 `plains`，后续再扩到 `savanna`。
- 最小间距：建议按区块网格控制，避免基地过密。
- 高度与坡度：超过阈值放弃生成，避免悬空或埋地。
- 世界边界与区块安全：仅在目标区块及邻区块可访问时执行放置。

## 8. 推荐最小可用版本（MVP）

- 仅做 1 个基地模板。
- 仅在平原低概率生成。
- 模板中放 1~2 个载具生成器方块。
- 暂不做复杂战利品和 AI 巡逻，先验证“结构 + 生成器”主链路。

## 9. 风险与注意项

- 1.7.10 无原生现代结构模板系统，需要自建模板读取与放置逻辑。
- 大模板生成可能引起卡顿，需控制每次生成工作量。
- 结构与地形冲突处理（整平/填坑）要提前设计，不然观感差。
- 多人服中应保证仅服务端执行结构落地，避免重复生成。

## 10. 分阶段实施计划

1. 阶段A：搭建世界生成入口 + 规则配置读取。
2. 阶段B：接入模板读取与旋转放置。
3. 阶段C：基地内生成器方块联动验证。
4. 阶段D：扩展多模板池、战利品与阵营化内容。

## 11. 配置文件化决策（全 txt）

- 结论：可行，且更贴合当前项目风格（`helicopters/planes/tanks/blocks/gunners` 同类文本配置链路）。
- 建议：结构系统全部采用 `txt` 配置，`schem` 只作为模板数据文件。
- 优势：
  - 与现有 `MCH_InfoManagerBase` / `loadItemData` 机制一致，维护门槛低；
  - 方便服主手改；
  - 和现有 `blocks/*.txt` 联动自然。

## 12. txt 配置目录建议

- `assets/mcheli/structures/*.txt`：结构定义。
- `assets/mcheli/structure_rules/*.txt`：生成规则。
- `assets/mcheli/structure_pools/*.txt`：模板池权重。
- `assets/mcheli/structures/schems/*.schem`：模板本体。

## 13. txt 字段示例

### 13.1 结构定义（`structures/base_small.txt`）

```txt
DisplayName = Base Small
; 结构显示名（字符串，1-64字符）
SchemFile = base_small.schem
; 模板文件名（字符串，必须存在于 assets/mcheli/structures/schems/ 下）
Size = 64,24,64
; 模板尺寸（整数, X,Y,Z，范围 1-512,1-256,1-512）
Anchor = 32,1,32
; 锚点坐标（整数, X,Y,Z，范围 0<=X<SizeX, 0<=Y<SizeY, 0<=Z<SizeZ）
AllowRotate = true
; 是否允许旋转（布尔：true/false）
AllowMirror = false
; 是否允许镜像（布尔：true/false）
FlattenPadding = 6
; 落地整平边距（整数，范围 0-32）
FoundationBlock = minecraft:stonebrick:0
; 地基方块（命名空间ID:meta，meta范围 0-15）
Marker = MCH_SPAWNER_A,base_spawner_alpha
; 模板标记替换（MarkerTag,blockInfoName；可重复多行）
Marker = MCH_WP_A1,wp_a1
; 模板标记替换（MarkerTag,blockInfoName；可重复多行）
```

### 13.2 生成规则（`structure_rules/plains_base.txt`）

```txt
Enable = true
; 启用规则（布尔：true/false）
Pool = military_base
; 关联模板池ID（字符串，需在 structure_pools/*.txt 存在）
Dimension = 0
; 维度白名单（整数列表，建议范围 -128 到 127）
Biome = plains,savanna
; 生物群系白名单（字符串列表，英文ID，小写）
GridSpacingChunk = 48
; 网格间距（区块，整数，范围 1-4096）
Chance = 0.18
; 命中候选点后的生成概率（浮点，范围 0.0-1.0）
HeightMin = 62
; 最低生成高度（整数，范围 1-255）
HeightMax = 90
; 最高生成高度（整数，范围 1-255，且 >= HeightMin）
SlopeMax = 4
; 最大坡度（整数，单位可按“最高点-最低点”实现，范围 0-64）
RejectLiquid = true
; 是否拒绝液体地表（布尔：true/false）
```

### 13.3 模板池（`structure_pools/military_base.txt`）

```txt
Entry = base_small,70
; 池项格式：结构ID,权重；权重整数范围 1-100000；可重复多行
Entry = base_large,30
; 池项格式：结构ID,权重；权重整数范围 1-100000；可重复多行
```

### 13.4 参数范围总览（建议）

- `DisplayName`：字符串，`1-64` 字符。
- `SchemFile`：字符串，必须是已存在的模板文件名。
- `Size`：`X,Y,Z` 整数，建议 `X/Z:1-512`，`Y:1-256`。
- `Anchor`：`X,Y,Z` 整数，必须在 `Size` 包围盒内。
- `AllowRotate` / `AllowMirror` / `Enable` / `RejectLiquid`：布尔（`true/false`）。
- `FlattenPadding`：整数 `0-32`。
- `FoundationBlock`：`namespace:block:meta`，`meta` 建议 `0-15`。
- `Dimension`：整数列表，建议 `-128~127`。
- `Biome`：小写字符串列表，需与运行环境生物群系ID一致。
- `GridSpacingChunk`：整数 `1-4096`。
- `Chance`：浮点 `0.0-1.0`。
- `HeightMin/HeightMax`：整数 `1-255`，且 `HeightMax >= HeightMin`。
- `SlopeMax`：整数 `0-64`（实现上可定义为样本区域最大高差）。
- `Entry`：`结构ID,权重`，权重整数 `1-100000`。

## 14. 关键实现建议（对应 txt 体系）

- 新增 `MCH_StructureInfo` / `MCH_StructureInfoManager`：加载 `structures/*.txt`。
- 新增 `MCH_StructureRuleInfo` / `MCH_StructureRuleManager`：加载 `structure_rules/*.txt`。
- 新增 `MCH_StructurePoolInfo` / `MCH_StructurePoolManager`：加载 `structure_pools/*.txt`。
- 新增 `MCH_WorldStructureGenerator`（`IWorldGenerator`）：区块触发、选址、放置、后处理。
- 在 `MCH_MOD` 初始化阶段注册 `registerWorldGenerator`，并加载三类结构配置。
- 保留与 `blocks/*.txt` 的后处理联动：通过 `Marker` 映射将模板标记点替换为对应配置生成器方块/航点块。

## 15. 运行时结构数据决策（更新）

- 决策：军事基地世界生成阶段不再直接读取通用 `.schem`，改为读取 MCHR 自有结构资产。
- 自有结构资产格式：
  - 元数据：`config/mcheli/structures_runtime/meta/<name>.txt`
  - 方块体：`config/mcheli/structures_runtime/blob/<name>.nbt`
- `.schem` 的定位：只作为导入源文件，不作为运行时最终格式。
- 目的：避免跨存档场景中的方块 ID 映射漂移，降低“变块”风险。

## 16. 资产生产与校验流程（推荐）

1. 建模阶段：
   - 可继续使用创世神搭基地。
2. 入库阶段（二选一）：
   - `capture` 直接从世界选区捕获为自有结构；
   - `importschem` 把 `.schem` 单向导入为自有结构。
3. 质量校验：
   - 使用 `validate` 检查未知方块、越界、关键 NBT 问题。
4. 落地验收：
   - 使用 `place` + `verify` 对比结构与世界一致性。
5. 上线前检查：
   - 验证生成器 `BlockInfoName` 修复和运行态清洗是否生效。

## 17. 命令介绍（结构链路）

- `/mcheli struct capture <name> <x1> <y1> <z1> <x2> <y2> <z2>`
  - 作用：从选区捕获结构到 `meta+blob`。
- `/mcheli struct place <name> <x> <y> <z> [rot]`
  - 作用：按名称语义放置结构（`rot=0/90/180/270`）。
  - 说明：放置后会执行关键块 `BlockInfoName` 修复。
- `/mcheli struct list`
  - 作用：列出已保存结构。
- `/mcheli struct validate <name>`
  - 作用：静态校验结构资产质量。
- `/mcheli struct verify <name> <x> <y> <z> [rot]`
  - 作用：对比当前世界与结构资产的一致性。
- `/mcheli struct importschem <name> <schemPath>`
  - 作用：将 `.schem` 单向导入为 `meta+blob`。
- `/mcheli spawnerfreeze true|false|status`
  - 作用：冻结/解冻生成器，避免导入导出过程刷实体干扰。

## 18. 现状与注意事项（代码级）

- 已有能力：
  - `capture/place/list/validate/verify/importschem` 已接入命令链。
  - `place` 阶段已实现关键块 `BlockInfoName` 修复。
  - 对 `MCH_ConfigSpawnerTileEntity` 已加运行态 NBT 清洗，防止导入后“长时间发呆不刷载具”。
- 当前限制：
  - `.schem` 导入器当前对方块 `meta` 支持不完整（默认按 `0` 处理），复杂方块朝向/变体可能丢失。
  - 世界生成入口（`IWorldGenerator`）尚未正式接入，需要按阶段A落地。

## 19. 下一步实施建议（面向军事基地生成）

1. 先接入 `MCH_WorldStructureGenerator`，运行时只读 `meta+blob`。
2. 实现规则文件加载（`structure_rules/*.txt`）并先支持最小字段：
   - `Enable/Dimension/Biome/GridSpacingChunk/Chance/HeightMin/HeightMax/SlopeMax`。
3. 先做单模板平原低概率生成（MVP），跑通“基地落地 + 生成器工作”。
4. 再补 `.schem` 导入器的 `meta` 还原增强与模板池随机化。

## 20. 实施步骤（可直接开工）

### 20.1 阶段A：世界生成入口（1-2天）

1. 新增 `MCH_WorldStructureGenerator`（实现 `IWorldGenerator`），并在 `MCH_MOD` 初始化阶段注册。
2. 在生成器中加入基础门控：
   - 仅服务端执行；
   - 维度白名单；
   - 生物群系白名单；
   - 区块网格间距与概率门控。
3. 先硬编码读取一个结构名（例如 `base_small`）进行最小闭环验证。
4. 验收标准：
   - 世界运行中可触发一次基地生成；
   - 无客户端重复生成；
   - 生成位置日志可追踪（区块坐标、规则命中原因）。

### 20.2 阶段B：结构放置器接入（1-2天）

1. 新增 `MCH_StructurePlacer`，复用当前 `struct place` 的核心逻辑：
   - `meta+blob` 读取；
   - 旋转放置（0/90/180/270）；
   - `BlockInfoName` 修复；
   - 生成器运行态 NBT 清洗。
2. 生成器中调用 `MCH_StructurePlacer`，替代直接命令路径。
3. 验收标准：
   - 同一结构可由“命令放置”和“世界生成”得到一致结果；
   - 关键生成器方块不会出现“发呆半天不刷”。

### 20.3 阶段C：规则文件化（1-2天）

1. 新增 `structure_rules/*.txt` 解析器（建议 `MCH_StructureRuleInfo/Manager`）。
2. 先支持最小字段：
   - `Enable`
   - `Dimension`
   - `Biome`
   - `GridSpacingChunk`
   - `Chance`
   - `HeightMin/HeightMax`
   - `SlopeMax`
3. 生成器改为按规则文件驱动，不再硬编码。
4. 验收标准：
   - 改配置无需改代码即可调整生成行为；
   - 非白名单维度/群系不生成。

### 20.4 阶段D：MVP联调与回归（1天）

1. 资产准备：
   - 用 `capture` 或 `importschem` 入库一个基地结构；
   - `validate` 确认结构质量；
   - `verify` 确认落地一致性。
2. 世界实测：
   - 新建两张独立存档，验证跨存档不变块；
   - 检查基地内生成器是否按配置正常刷载具。
3. 验收标准：
   - 结构稳定生成；
   - 关键方块语义一致；
   - 日志无关键错误。

### 20.5 阶段E：增强项（后续）

1. 补模板池（`structure_pools/*.txt`）与权重随机。
2. 补后处理（标记替换、阵营点位、箱子/守军扩展）。
3. 增强 `.schem` 导入器对方块 `meta` 的还原能力。

## 21. 多世界兼容性调研（服务器）

### 21.1 结论

- 方案可用于多世界，但需要区分服务器形态：
  - Forge 原生多维度：可直接兼容。
  - Bukkit/Spigot 多世界插件：仅在 Forge+Bukkit 混合核心（如 Cauldron/Thermos/Mohist）场景可谈兼容，纯 Forge 不支持 Bukkit 插件体系。
- 当前“运行时读取 `meta+blob`”路线本身对多世界是友好的，因为结构资产不绑定单一世界。

### 21.2 关键风险点

- 世界识别维度不足：
  - 仅用 `dimensionId` 可能无法区分某些多世界插件场景，建议同时使用 `worldName`。
- 生成去重冲突：
  - 若只做全局去重，多世界可能误判或重复生成。
- 规则粒度不够：
  - 仅维度/群系筛选不足以表达“某个世界开、某个世界关”。
- 生命周期时序差异：
  - 混合核心下世界加载顺序可能变化，生成器注册与配置加载要做时序保护。

### 21.3 配置与代码补充建议

- 规则字段新增：
  - `WorldNameWhitelist`
  - `WorldNameBlacklist`
- 生成记录按世界隔离：
  - 建议键：`worldName + dimensionId + chunkX + chunkZ`
- 日志增强：
  - 每次判定输出 `worldName/dimensionId/chunk/ruleId`。
- 安全门控：
  - 仅服务端、仅区块可访问时执行放置。

### 21.4 实施计划调整建议

- 阶段A补充：
  - 在门控中加入 `worldName` 级别过滤与日志。
- 阶段C补充：
  - 规则解析加入 `WorldNameWhitelist/Blacklist`。
- 阶段D补充：
  - 验收从“单世界回归”升级为“多世界回归”（至少两张世界分别验证）。
- 阶段E补充：
  - 增加跨世界统计与冲突检测（生成次数、拒绝原因分布）。
