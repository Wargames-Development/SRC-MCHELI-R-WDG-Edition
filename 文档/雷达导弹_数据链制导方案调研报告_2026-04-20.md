# 雷达导弹数据链制导方案调研报告（2026-04-20）

## 1. 目标与范围

本方案仅讨论**机载雷达链路（EnableRadar）**对雷达导弹的中继制导，不涉及武器层主动雷达弹既有导引逻辑的删除与重写。

目标武器范围：

- `ATMissile`、`AAMissile`
- 仅对以下雷达子模式生效：
  - `ActiveRadar = true`
  - `PassiveRadar = true`
  - `SemiActiveRadar = true`
- 明确排除：`AntiRadiationMissile = true`

新增参数：

- `EnableDataLink = true`（默认对上述目标类型启用）
- `OnlyDataLink = false`（仅当 `EnableDataLink=true` 有效）
  - `OnlyDataLink=true`：只允许数据链模式，不允许普通模式


## 2. 现状调研结论（代码）

### 2.1 可复用的现有能力

- 武器模式框架：`modeNum/fixMode/currentMode/switchMode`
  - 入口：`MCH_WeaponInfo` + `MCH_WeaponBase`
- 雷达导弹三类标志已存在：
  - `activeRadar/passiveRadar/semiActiveRadar`
- 雷达干扰基础已存在：
  - `ECM`：`isECMJammerUsing()/ecmJammerUseTime/jammingTick`
  - `chaff`：`chaffUseTime`
- 机载雷达状态接口已存在：
  - `getRadarSelectedTargetId()`
  - `getRadarTrackingTargetId()`
  - 当前支持 `SRC/TWS/GMTI_SRC/GMTI_TWS`

### 2.2 现有耦合风险

- `SemiActiveRadar` 可与 `ActiveRadar` 共存（子集关系），行为优先级需要显式定义。
- `AntiRadiationMissile` 可与 `Active/SemiActive` 共存，必须单独排除数据链逻辑，避免破坏反辐射导引。
- 当前导弹锁定逻辑在 `MCH_WeaponGuidanceSystem` 与 `MCH_EntityBaseBullet` 分散，需要集中加一层“数据链门控”。


## 3. 需求拆解与统一语义

为避免歧义，先给统一语义定义：

- **普通模式（Normal）**：不改变现有武器行为。
- **数据链模式（DL）**：使用机载雷达状态作为中继引导来源。
- **导弹失联（Link Lost）**：DL 源消失后不再提供中继修正，仅保留导弹自身已存在运动学（惯性/当前导引器）。
- **主动雷达捕获（ARH Capture）**：`ActiveRadar` 导弹自身导引头已获得目标，后续优先导弹自身导引。


## 4. 模式设计（独立数据链状态，不占用武器 mode 槽位）

核心原则：

- **不复用 `ModeNum/FixMode`**，避免与 AT 攻顶等既有模式冲突。
- 数据链作为独立布尔状态（建议命名 `dataLinkMode`），与武器现有 `mode` 并行存在。
- 模式切换键仍可用于“切换数据链状态”，但不改变武器原有 `currentMode` 编号。

显示规则：

- 中文：`[数据链]`
- 英文：`[DL]`

模式开关建议：

- `EnableDataLink=false`：无数据链状态（保持当前）
- `EnableDataLink=true && OnlyDataLink=false`：可手动开/关 `dataLinkMode`
- `EnableDataLink=true && OnlyDataLink=true`：强制 `dataLinkMode=true`（锁定，不允许关闭）


## 5. 三类雷达导弹的数据链规则

## 5.1 PassiveRadar（数据链模式）

发射前门限：

- 机载雷达必须处于 `SRC/GMTI_SRC/TWS/GMTI_TWS`
- 必须存在**跟踪目标**（tracking）
- 目标满足 `MaxDegreeOfMissile` 发射角门限

发射后：

- 数据链为唯一引导来源（其自身被动雷达搜跟逻辑在 DL 下封禁）
- 若机载雷达因 `ECM/chaff/手动脱锁` 失去目标，导弹立即失联，不再可被中继引导

## 5.2 SemiActiveRadar（数据链模式）

发射前门限：

- 与 PassiveRadar 相同（必须 tracking）

发射后：

- DL 下封禁半主动本体“持续照射/跟踪获取”链路，只保留运动学门限（如 `MaxDegreeOfMissile`）
- 若机载雷达被 `ECM/chaff` 干扰导致脱锁，则该导弹失联
- 雷达可改锁其它目标并发射/引导其它导弹（不要求回锁同一目标）

## 5.3 ActiveRadar（数据链模式）

发射前门限：

- 雷达模式 `SRC/GMTI_SRC/TWS/GMTI_TWS`
- `SRC/GMTI_SRC`：要求 tracking
- `TWS/GMTI_TWS`：允许 tracking 或 selected
- 目标满足 `MaxDegreeOfMissile` 发射角门限

发射后（并行策略）：

- 主动雷达导引与数据链并行，**主动雷达优先**
- 主动雷达未捕获前：可用数据链中继修正
- 主动雷达捕获后：停止使用数据链
- 若机载雷达被干扰但导弹主动雷达仍可继续捕获/跟踪，则导弹仍可继续
- 若机载雷达与导弹主动雷达均被干扰，导弹失联


## 6. 冲突优先级与排除规则

建议优先级（高 -> 低）：

1. `AntiRadiationMissile=true`：直接排除数据链功能（即使 EnableDataLink=true）
2. `OnlyDataLink=true`：强制数据链模式
3. `ActiveRadar` 与 `SemiActiveRadar` 同时为真时：
   - DL 下按 ActiveRadar 流程优先（并行 + ARH 优先）
4. `PassiveRadar` 与其它雷达模式并存时：
   - 仅在武器实际子模式命中 Passive 分支时启用其规则（与数据链状态解耦）


## 7. 建议实现架构（不改现有主逻辑的最小侵入）

新增小型策略层（建议）：

- `MCH_DataLinkPolicy`（新类，纯判定）
  - `isDataLinkMode(weapon)`
  - `canFireWithDataLink(weapon, ac, player, radarState, target)`
  - `resolvePostLaunchGuidance(weaponInfo, missileState, radarState, seekerState)`

新增导弹运行态字段（建议）：

- `dlEnabled`、`dlLinkedTargetId`、`dlLost`
- `arhCaptured`（仅 ActiveRadar）

挂接点建议：

- 发射前判定：`MCH_WeaponATMissile.shot()` / `MCH_WeaponAAMissile.shot()`
- 发射参数传递：`optionParameter` / 导弹实体初始化
- 飞行中更新：`MCH_EntityAAMissile` / `MCH_EntityATMissile` 的 update/homing 分支
- 名称后缀显示：武器 `getName()` 或 HUD 文案拼接处


## 8. 门限清单（实现时必须一致）

发射门限：

- 雷达状态门限（selected/tracking + 模式约束）
- 角度门限（`MaxDegreeOfMissile`）
- 目标有效门限（非同阵营、非干扰态）

链路门限：

- 机载雷达目标是否仍有效
- 目标是否进入 ECM/chaff 持续期
- 主动雷达是否已捕获（ActiveRadar）


## 9. 测试矩阵（最小必要）

- `PassiveRadar + DL`：
  - 锁定发射成功
  - 雷达脱锁后导弹失联
- `SemiActiveRadar + DL`：
  - 干扰脱锁后失联
  - 切换到另一目标可继续作战（新弹）
- `ActiveRadar + DL`：
  - 未捕获时依赖 DL
  - 捕获后切换自导
  - 雷达断链但 ARH 已捕获仍可追
  - 双重干扰（机载+导弹）失联
- 互斥验证：
  - `AntiRadiationMissile=true` 时 DL 不生效
- 模式验证：
  - `OnlyDataLink=true` 只能 `[数据链]/[DL]`


## 10. 复杂点与风险

- 复杂点不在“加参数”，而在**三类导弹的后续导引状态机不一致**。
- 最大风险是把 ActiveRadar 并行逻辑做成覆盖逻辑，导致“主动捕获后仍被 DL 干扰”。
- 次风险是 `SemiActiveRadar` 与 `ActiveRadar` 并存时分支顺序错误。


## 11. 建议分阶段落地

阶段 1（低风险）：

- 参数接入（EnableDataLink/OnlyDataLink）
- 数据链状态切换与文案显示 `[数据链]/[DL]`（不改武器 mode 编号）
- `AntiRadiationMissile` 排除

阶段 2（中风险）：

- 发射前门限（雷达状态 + 角度 + 同阵营/干扰过滤）

阶段 3（高风险）：

- 飞行中并行逻辑（尤其 ActiveRadar 优先 + 捕获切换）
- 失联状态处理与日志


## 12. 本报告结论

你的思路是完整且可落地的，关键在于先把“模式门控”和“后续导引状态机”拆开实现。  
建议先做阶段 1/2，稳定后再上阶段 3 的并行导引优先级。

## 13. 动画与交互规范（新增）

本节为本次追加需求的强制 UI/动画行为定义。

### 13.1 雷达页导弹可视化与连线

- 数据链模式下，导弹在雷达页可显示，不经过扫描概率命中链路。
- 显示门限：只要导弹处于机载雷达照射范围内即可显示（不受 scan hit 概率抑制）。

- `PassiveRadar` / `SemiActiveRadar` 导弹：
  - 发射后在雷达页显示导弹点位。
  - 导弹与当前目标之间绘制**虚线**。

- `ActiveRadar` 导弹：
  - 在“数据链中继阶段（主动雷达未捕获）”导弹与目标绘制**虚线**。
  - 当导弹主动雷达捕获目标后，连线切换为**实线**（主动雷达优先）。

### 13.2 链路中断时的线条规则

- `PassiveRadar`、`SemiActiveRadar`、以及 `ActiveRadar` 的“未捕获阶段”：
  - 若机载雷达脱锁（含干扰脱锁/手动断锁），导弹-目标**虚线立即消失**。

- `ActiveRadar` 已捕获阶段：
  - 即便机载雷达断锁，导弹-目标**实线继续保留**（由导弹自身主动雷达维持）。
  - 但若此时导弹自身主动雷达受干扰导致失效，则**实线消失**。

### 13.3 数据链模式下的发射门限提示文案

- `PassiveRadar` / `SemiActiveRadar`（DL 模式）：
  - 无 `SRC/GMTI_SRC/TWS/GMTI_TWS` 锁定目标时禁止发射。
  - 中文提示：`请先锁定目标`
  - 英文提示：`Please lock a target first`

- `ActiveRadar`（DL 模式）：
  - 无以下任一状态时禁止发射：
    - `SRC/GMTI_SRC` 的 tracking
    - `TWS/GMTI_TWS` 的 selected 或 tracking
  - 中文提示：`请先选择或锁定目标`
  - 英文提示：`Please select or lock a target first`

### 13.4 数据链模式下的门限可视化叠加

- 在 DL 模式选择/锁定目标时，渲染白色门限环：
  - 线宽：`2`
  - FOV 角度：当前武器 `MaxDegreeOfMissile`

- 当被选择或锁定目标位于 `MaxDegreeOfMissile` 门限内时：
  - 在 BVR 框内额外渲染两个小型双红圈（尺寸接近 BVR 框）。

### 13.5 实现注意

- 本节全部规则针对机载雷达数据链 UI，不影响普通模式下的原有武器导引显示。
- “导弹显示不经过扫描概率”仅限导弹符号与导弹-目标连线，不改变雷达对常规目标的探测概率模型。

## 14. 阶段推进补充（本轮）

本轮实现目标从“仅发射门限”推进到“飞行中状态机”：

- 新增导弹运行态：
  - `dataLinkRelayMode`
  - `activeRadarCaptured`
- 状态机约束：
  - `Passive/SemiActive + DL`：链路存在时持续追踪雷达目标；链路丢失后断链并惯性飞行（不再自主重搜）。
  - `Active + DL`：中继阶段不自主重搜；进入捕获态后切换到导弹自身主动雷达导引。
- 客户端锁定更新链路：
  - 在 `lock/onUnlock` 流程中，将当前雷达 `selected/tracking` 目标同步到已发射导弹目标，支撑“飞行中中继目标更新”。
