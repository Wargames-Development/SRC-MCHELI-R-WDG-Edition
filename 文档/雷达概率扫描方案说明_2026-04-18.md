# 雷达概率扫描方案说明（2026-04-18）

## 1. 目标

- 在不做复杂雷达回波仿真的前提下，提升 BVR 索敌体验。
- 让雷达具备“扫描节奏、漏检概率、目标短时保持”三种核心特征。
- 保持实现轻量，尽量复用现有 `MCH_RenderBVRLockBox` / `MCH_RenderLeadCircle` 渲染链路。

## 2. 方案结论

该方案可行，且非常适合当前阶段。

- 不做回波处理，改用概率判定“本次扫描是否发现目标”。
- 一旦发现目标，则显示超视距框一段时间（TTL 保持），避免闪烁。
- 保留已有 `RadarMaxTargetRange`，并新增扫描角度与扫描周期参数。

## 3. 建议参数

- `EnableBVR=true`
- `RadarMaxTargetRange=3000`
- `RadarScanAzimuthDeg=120`
- `RadarScanElevationDeg=40`
- `RadarScanTick=12`
- `RadarDetectChanceBase=0.75`
- `RadarContactHoldTick=40`

参数说明：

- `RadarScanAzimuthDeg`：水平扫描扇区角度（机头左右总角度）。
- `RadarScanElevationDeg`：垂直扫描扇区角度（机头上下总角度）。
- `RadarScanTick`：扫描间隔，单位 tick。
- `RadarDetectChanceBase`：基础发现概率，范围建议 `0.0~1.0`。
- `RadarContactHoldTick`：命中后显示保持时长，单位 tick。

## 4. 判定流程（轻量版）

每到扫描 tick 执行一次：

1. 候选目标过滤（距离、目标类型、是否友军、最大显示距离）。
2. 扫描几何过滤（方位角是否在扇区内、俯仰角是否在扇区内）。
3. 概率判定：`rand < p` 则目标被发现。
4. 发现则写入缓存：`contactCache[targetId] = RadarContactHoldTick`。

每 tick 衰减缓存：

- `ttl -= 1`
- `ttl > 0` 继续显示 BVR 框
- `ttl <= 0` 移除目标

## 5. 概率公式建议（第一版）

第一版先用简单模型，避免调参过重：

`p = RadarDetectChanceBase * angleFactor * rangeFactor`

- `angleFactor`：越接近机头中心越高（例如 0.6~1.0）。
- `rangeFactor`：越远越低（例如 0.5~1.0）。

后续可选扩展（第二版）：

- 目标隐身系数（`stealth`）
- 电子干扰（`jammingTick`）
- 目标高度差修正

## 6. 优点与风险

优点：

- 成本低，几乎不改现有武器制导逻辑。
- 体验显著提升，雷达不再“永远稳定透视”。
- 可配置性强，适配不同载机雷达档位。

风险：

- 概率过低会导致“几乎看不到目标”。
- 概率过高会退化为“几乎实时透视”。

规避建议：

- 初始建议：`ScanTick=10~15`、`HoldTick=30~50`、`Base=0.70~0.85`。

## 7. 落地步骤（建议）

1. 在 `MCH_AircraftInfo` 新增并解析扫描参数。
2. 在 `MCH_RenderBVRLockBox` 增加 `contactCache + ttl`。
3. 将当前“实时可见即显示”改为“扫描命中缓存后显示”。
4. `MCH_RenderLeadCircle` 只从“已发现缓存”中选择目标。
5. 加一个简单 debug 输出（扫描次数、命中数、缓存数）便于调参。

## 8. 实施边界

- 第一阶段仅作用于“显示层”（BVR 框/预瞄提示）。
- 武器实际锁定与导弹制导暂不绑定该概率机制。
- 若后续需要更真实，可再把发现状态迁移到服务端统一判定。
