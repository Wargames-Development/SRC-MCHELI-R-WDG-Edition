# gunner 配置文件化与独立页面方案调研（2026-04-16）

## 1. 目标

- 将当前“硬编码的 gunner 物品与类型”改为“可配置文件定义”。
- 新增一个独立的 gunner 创造页（不再和通用 item 页混在一起）。
- 给出适合当前项目架构的实现路径与推荐参数设计。

---

## 2. 当前代码现状梳理

## 2.1 gunner 实体能力（核心在 `MCH_EntityGunner`）

- gunner 目标类型是固定枚举：
  - `TARGET_MONSTER=0`
  - `TARGET_PLAYER=1`
  - `TARGET_AA_AMMO=2`
  - `TARGET_ENEMY=3`
- 运行态有大量 AI 行为（坦克/直升机/固定翼驾驶、目标选择、反制释放等），但可持久化字段并不多，主要是：
  - `TeamName`
  - `TargetType`
  - `isCreative`
  - `ownerUUID`
  - `stupidGunner`
- 这意味着：当前体系更像“同一实体 + 少量行为开关”，不是多种独立子类实体。

## 2.2 生成入口（物品/命令/方块）

- 物品入口：`MCH_ItemSpawnGunner`
  - 通过道具字段 `targetType`、`isStupid` 决定生成行为。
  - 对阵营 gunner（`targetType=1`）要求玩家有队伍。
- 命令入口：`/addgunner`
  - 支持 `friendly / player(pvp) / aa / enemy`。
  - `pvp` 支持传 teamname。
- 方块入口：`MCH_ConfigSpawnerTileEntity`
  - 已支持 `SpawnGunner/GunnerMode/GunnerTargetType/GunnerSeatIndex/...` 等配置，属于“局部配置化”。

## 2.3 当前“硬编码”位置

- `MCH_MOD#registerItemSpawnGunner()` 里写死了 6 个 gunner 物品：
  - `spawn_gunner_vs_monster`
  - `spawn_gunner_vs_player`
  - `gunner_aa`
  - `gunner_enemy`
  - `gunner_friendly_stupid`
  - `gunner_enemy_stupid`
- 这些物品统一注册在 `creativeTabs`（通用 item 页），尚无独立 gunner 页。

## 2.4 与全局配置关系

- `MCH_Config` 里已有不少 gunner 全局参数（尤其飞行 AI 搜索半径/状态持续时间）。
- 目前它们是“全局统一值”，不是“每种 gunner profile 单独值”。

---

## 3. 可行性结论

- **完全可行**，且与现有架构兼容。
- 最适合做法是：引入 `GunnerInfo` 配置体系，驱动“spawn gunner item”的注册与属性，而不是重做 gunner 实体类层次。
- 新增独立 gunner 页面也可低风险实现（复用现有 `MCH_CreativeTabs`）。

---

## 4. 推荐实施路线（按风险从低到高）

## 4.1 Phase A（推荐先做，低风险）

- 新增 `assets/mcheli/gunners/*.txt` 配置目录。
- 新增：
  - `mcheli.mob.MCH_GunnerInfo`（参数对象）
  - `mcheli.mob.MCH_GunnerInfoManager`（加载管理）
- 新增一个可配置化物品类（可复用 `MCH_ItemSpawnGunner`，或加薄封装）：
  - 通过 `gunnerInfoName` 查配置，生成 gunner 时按配置赋值。
- `MCH_MOD` 新增 `creativeTabsGunner`，并将 gunner 物品注册到该页。
- 保留原有 6 个硬编码物品作为兼容兜底（先不删）。

## 4.2 Phase B（中风险）

- 命令 `/addgunner` 增加 profile 参数：
  - 例如 `/addgunner profile <name> <x> <y> <z> <r>`
- 方块生成器可选支持直接引用 gunner profile：
  - 例如 `GunnerProfile=aa_default`

## 4.3 Phase C（高风险，不建议首轮）

- 把 `MCH_Config` 中部分全局 gunner AI 参数下沉到 profile（每种 gunner 独立调参）。
- 这会触及 `MCH_EntityGunner` 大量行为路径，建议后置。

## 5. 推荐配置参数设计

## 5.1 必选核心参数（首版建议）

- `DisplayName`
  - 含义：物品默认语言显示名。
  - 建议：简短且可区分用途，例如 `Gunner [AA]`。
- `AddDisplayName=zh_CN,...`
  - 含义：多语言显示名（推荐至少补 `zh_CN`）。
  - 建议：中文服写全称，例如 `炮手[反导]`。
- `ItemName`
  - 含义：注册名（唯一键）。
  - 建议：全小写+下划线，例如 `gunner_aa_cfg`。
- `TargetType`
  - 含义：目标类型（`monster|player|aa|enemy` 或 `0~3`）。
  - 建议：
    - 反导炮手：`aa`
    - 阵营对抗：`player`
    - 友好守备：`monster`
    - 全敌对：`enemy`
- `StupidGunner`
  - 含义：是否强制进入愚人模式。
  - 建议：默认 `false`，交给概率参数控制更灵活。
- `PrimaryColor`
  - 含义：图标主色（十六进制）。
  - 建议：按职能区分色系（反导偏绿，阵营偏红/蓝）。
- `SecondaryColor`
  - 含义：图标辅色（十六进制）。
  - 建议：与主色形成对比，避免图标难辨认。
- `UseLayeredIcon`
  - 含义：是否启用双层图标。
  - 建议：`true`（视觉识别更清晰）。

## 5.2 阵营相关参数（仅 `TargetType=player` 生效）

- `TeamMode=player|fixed|none`
  - `player`：沿用当前“取使用者队伍”
  - `fixed`：使用 `FixedTeamId`
  - `none`：不强制队伍（一般不建议）
- `FixedTeamId`
  - 含义：固定队伍ID。
  - 建议：短ID（如 `red`、`blue`），避免中英文空格。
- `AutoCreateTeam`
  - 含义：队伍不存在时自动创建。
  - 建议：`true`（减运维成本）。
- `FixedTeamDisplayName`
  - 含义：队伍显示名称。
  - 建议：和阵营文案保持一致，如 `RED`、`北约`。
- `FixedTeamColor`
  - 含义：队伍颜色（十六进制）。
  - 建议：红蓝绿等强识别颜色，便于战场辨认。

## 5.3 生成与挂载规则（可选）

- `MountSearchRange`
  - 含义：右键生成时的挂载目标检索半径。
  - 建议：`4.0~6.0`，过大容易误挂载。
- `AllowMountAircraft`
  - 含义：是否允许挂到主座位。
  - 建议：防空炮塔场景 `false`，综合场景 `true`。
- `AllowMountSeat`
  - 含义：是否允许挂到副座位。
  - 建议：大多数场景 `true`。
- `AllowReplaceExistingGunner`
  - 含义：是否允许替换已有 gunner。
  - 建议：默认 `false`，避免误替换战场单位。
- `RequirePlayerTeamWhenPvp`
  - 含义：阵营炮手是否要求使用者必须有队伍。
  - 建议：服主严谨管理设 `true`，沙盒地图可设 `false`。

## 5.4 进阶参数（二期可加）

- `DropItemName`
  - 含义：死亡后掉落物重定向。
  - 建议：自定义 profile 必配，避免掉回硬编码道具。
- `AllowAutoCountermeasure`
  - 含义：是否允许自动释放箔条/干扰。
  - 建议：反导炮手 `true`，普通守备 `false`。
- `VehicleDriveStyle`
  - 含义：载具机动风格（保守/激进）。
  - 建议：坦克 `保守`，空战机型 `激进`。

## 5.5 索敌范围参数（你本次新增需求）

- `SearchRangeGroundHorizontal`
  - 含义：对地目标水平索敌半径。
  - 建议：`80~260`，地面防守一般 `120~180`。
- `SearchRangeGroundVertical`
  - 含义：对地目标垂直索敌窗口。
  - 建议：`60~220`，复杂地形建议提高。
- `SearchRangeAirHorizontal`
  - 含义：对空目标水平索敌半径。
  - 建议：`220~600`，防空炮手建议 `400+`。
- `SearchRangeAirVertical`
  - 含义：对空目标垂直索敌窗口。
  - 建议：`180~500`，高空作战建议 `300+`。
- `SearchRangeFallbackToConfig`
  - 含义：未配置上述范围参数时是否回退全局 `MCH_Config`。
  - 建议：默认 `true`。

### 5.5.1 回退规则建议（重要）

- 规则1：若 profile 中写了范围参数，优先用 profile 值。
- 规则2：若 profile 未写某项，则回退：
  - 对地：`RangeOfGunner_VsMonster_* / RangeOfGunner_VsPlayer_*`（按 targetType 决定）
  - 对空：`GunnerPlaneSearchRadiusAir / GunnerPlaneSearchAltitudeWindow`
- 规则3：若 `SearchRangeFallbackToConfig=false` 且参数缺失，则用 profile 默认值并打印警告日志。

### 5.5.2 建议的参数示例（含中文注释）

```txt
SearchRangeGroundHorizontal=160
; 对地水平索敌半径（米）
SearchRangeGroundVertical=120
; 对地垂直索敌窗口（米）
SearchRangeAirHorizontal=480
; 对空水平索敌半径（米）
SearchRangeAirVertical=320
; 对空垂直索敌窗口（米）
SearchRangeFallbackToConfig=true
; 未配置时回退MCH_Config预设
```

## 5.6 扩展参数（统一收口）

- `FactionRole=normal|friendly|enemy|aa`
  - 含义：阵营 gunner 子角色（仅 `TargetType=player` 语境建议启用）。
  - 建议：
    - 常规阵营守军：`normal`
    - 偏防守阵营：`friendly`
    - 纯对抗阵营：`enemy`
    - 反导阵营：`aa`
- `StupidGunnerChance=0.0~1.0`
  - 含义：愚人模式概率（当 `StupidGunner=false` 时生效）。
  - 建议：
    - 严肃服：`0.0~0.05`
    - 轻娱乐服：`0.05~0.2`
- `StupidGunnerChanceByRole=normal:0.0|friendly:0.05|enemy:0.2|aa:0.0`（可选）
  - 含义：按角色覆写愚人概率。
  - 建议：未配置则回退 `StupidGunnerChance`。
- `AirWeaponPriority=type:weight|...`
  - 含义：对空武器优先级映射。
  - 建议示例：`aamissile:100|railgun:45|machinegun1:35|machinegun2:35|rocket:15`
- `GroundWeaponPriority=type:weight|...`
  - 含义：对地武器优先级映射。
  - 建议示例：`atmissile:90|asmissile:90|tvmissile:90|rocket:60|bomb:40|machinegun1:25|machinegun2:25|railgun:25`

### 5.6.1 扩展参数回退规则

- 规则1：若配置了 `AirWeaponPriority/GroundWeaponPriority`，则覆盖硬编码权重。
- 规则2：未配置时回退当前 `MCH_EntityGunner` 现有权重逻辑。
- 规则3：`StupidGunner=true` 优先级最高；否则走 `StupidGunnerChanceByRole`；仍缺失再走 `StupidGunnerChance`。
- 规则4：`FactionRole` 未配置时默认 `normal`。

## 5.7 接入与联动参数（跨章节补齐）

- `GunnerProfile`
  - 含义：方块/命令等入口指定的 gunner 配置档名（profile key）。
  - 建议：与 `ItemName`/文件名保持一致命名风格（全小写+下划线）。
- `CreativeTabIconGunner`
  - 含义：独立 gunner 创造页图标配置项（系统级）。
  - 建议：指向稳定存在的 gunner 物品注册名。
- `RegisterGunnerItemInDefaultTab`
  - 含义：是否在默认物品页保留 gunner 镜像注册（兼容开关，系统级）。
  - 建议：首轮迁移期 `true`，稳定后可改 `false`。

## 5.8 本轮新增参数（命中体验与射击节奏）

- `AllowLeadForAirTarget=true|false`
  - 含义：是否允许对空目标使用提前量计算（速度前置预测）。
  - 建议：
    - 反导/防空炮手：`true`
    - 娱乐/训练模式：`false`（更直观但命中率下降）
- `StupidAttackSectorScaleGround=1.0~2.0`
  - 含义：愚人模式下对地攻击扇区放大系数（仅地面载具语境）。
  - 建议：
    - 轻微放宽：`1.15~1.25`
    - 明显放宽：`1.3~1.5`
- `EnableShortBurst=true|false`
  - 含义：是否启用短点射节奏（仅对 `delay < 5` 的武器生效）。
  - 建议：默认 `false`，按 profile 精细开启。
- `ShortBurstFireTick`
  - 含义：短点射连续开火时长（tick）。
  - 建议：`8~25`（常用 `12~18`）
- `ShortBurstRestTick`
  - 含义：短点射休息时长（tick）。
  - 建议：`6~20`（常用 `8~14`）

### 5.8.1 新增参数回退规则

- 规则1：若 profile 未配置 `AllowLeadForAirTarget`，回退当前硬编码行为（默认启用提前量）。
- 规则2：`StupidAttackSectorScaleGround` 未配置时按 `1.0` 处理（不放大）。
- 规则3：仅当 `EnableShortBurst=true` 且武器 `delay < 5` 时启用点射节奏；否则沿用原连续开火逻辑。
- 规则4：若点射时长/休息时长缺失，回退默认值：`ShortBurstFireTick=14`、`ShortBurstRestTick=10`。

## 7. “单开 gunner 页”推荐做法

## 7.1 代码策略

- 在 `MCH_MOD` 新增：
  - `public static MCH_CreativeTabs creativeTabsGunner;`
- `preInit` 创建页面实例（命名如 `"MCH-Reforged Gunners"`）。
- `postInit` 设置图标（优先使用配置项，例如 `CreativeTabIconGunner`）。
- gunner 相关物品（硬编码 + 配置化新增）统一注册到 `creativeTabsGunner`。

## 7.2 兼容策略

- 首轮建议保留老页面镜像（可选开关）：
  - `RegisterGunnerItemInDefaultTab=true/false`
- 这样不会打断老玩家检索习惯。

## 9. 风险与注意事项

- `MCH_EntityGunner#setDead()` 当前掉落是按 `targetType + stupid` 走硬编码 item。
  - 若要完整配置化掉落，建议新增 `dropItemName` 并写入 NBT（否则自定义 profile 可能掉回默认物品）。
- 阵营逻辑和 scoreboard 强相关，`TeamMode=fixed` 需处理“队伍不存在”场景。
- `TARGET_AA_AMMO` 与载具武器/拦截场景耦合较深，建议首轮不要改其语义。

---

## 10. 最终建议

- 你这个需求最适合采用“**数据驱动 profile + 独立 gunner 页**”方案。
- 首轮优先做 Phase A：低风险、收益高、兼容好。
- 先不动 `MCH_EntityGunner` 的大段 AI 逻辑，把改动集中在“物品定义与生成入口”最稳。

## 11. 你提出的扩展点专项调研

## 11.1 阵营 gunner 从其它链路剥离，是否可行

- **可行，且建议做成“Faction 子体系”而不是改 targetType 枚举数量。**
- 当前 `MCH_EntityGunner` 里 `TARGET_PLAYER=1` 已代表“阵营对抗 gunner”。
- 推荐新增参数 `FactionRole`，用于在 `TargetType=player` 下细分行为，而不破坏现有 0~3 枚举：
  - `FactionRole=normal`（普通阵营）
  - `FactionRole=friendly`（友好阵营）
  - `FactionRole=enemy`（敌对阵营，保留可选）
  - `FactionRole=aa`（反导阵营）
- 实现上可在 `canAttackEntity(...)` 和 `updateTargetForWeapon(...)` 做 role 分流过滤，兼容成本低于新增实体子类。

## 11.2 愚人模式概率参数，是否可行

- **可行，建议做成 profile 级概率参数。**
- 当前仅有一处硬编码随机：`MCH_ItemSpawnGunner` 对 faction gunner `10%` 概率变愚人模式。
- 参数定义与推荐值已统一归并到 `5.6 扩展参数（统一收口）`。
- 生成公式建议：
  - 若 `StupidGunner=true`，强制愚人；
  - 否则按 `StupidGunnerChanceByRole -> StupidGunnerChance` 顺序判定。

## 11.3 对地/对空武器选择优先级配置化，是否可行

- **可行，且收益高。**
- 当前硬编码点在 `MCH_EntityGunner`：
  - `isWeaponTypeAllowedForContext(...)`
  - `getWeaponContextWeight(...)`
- 参数定义、示例与回退规则已统一归并到 `5.6 扩展参数（统一收口）`。

## 11.4 推荐新增参数清单（首批）

## 11.5 游戏性意义

- 阵营 gunner 剥离后，服主可把“阵营守军”和“中立守备”明确分开，减少混乱击杀逻辑。
- 愚人概率可控后，能保留随机趣味，同时避免“全图抽风”影响可控性。
- 武器优先级配置化后，能按地图需求做“防空导向”“反坦导向”“压制导向”三类模板，运营可维护性明显提升。

## 11.6 提前量、愚人扇区与短点射专项调研（本轮新增）

- 提前量现状：
  - 当前在 `MCH_EntityGunner#canAttackEntity(...)` 中，目标点按 `entity.motionX/Y/Z * tick` 前推后再解算 yaw/pitch，属于硬编码启用。
  - 结论：新增 `AllowLeadForAirTarget` 可行，推荐只作用于“对空目标”分支，避免地面目标误差放大。
- 愚人模式精度现状：
  - 当前愚人模式并非“索敌阶段加随机”，而是“瞄准阶段给 yaw/pitch 叠随机偏移”，位置同样在 `canAttackEntity(...)`。
  - 结论：文档里应修正表述为“瞄准随机偏移”。
- 愚人模式攻击扇区现状：
  - 是否可打受机体武器角限制（如 `isInAttackable(...)` 与机体 fire window 判断）约束。
  - 结论：可通过 `StupidAttackSectorScaleGround` 在地面载具语境放宽扇区门限，避免“炮口看似对准但被扇区硬卡”。
  - 风险：系数过大可能出现“穿越座舱逻辑盲区射击”的违和感，建议上限不超过 `1.5`。
- 短点射现状：
  - 当前不存在“delay<5 自动短点射”机制，连发武器通常持续压枪。
  - 结论：新增 `EnableShortBurst + FireTick + RestTick` 可行，建议挂在 gunner 实体 tick 层，按武器 delay 做开关。
  - 风险：若休息太长会导致反导火力断档，反导 profile 建议谨慎启用。
