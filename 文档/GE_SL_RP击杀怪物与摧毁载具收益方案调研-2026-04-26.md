# GE / SL / RP 击杀怪物与摧毁载具收益方案调研（2026-04-26）

## 1. 需求目标
- 玩家通过两类行为获得货币：  
  1) 击杀 MC 生物（怪物/生物）  
  2) 摧毁载具（飞机/坦克/直升机/车辆）
- 货币类型：`GE`、`SL`、`RP`。
- 货币 UI 图标：使用 `mcheli/textures/coins` 目录下同名 `png`（`GE.png`、`SL.png`、`RP.png`）。
- 目标原则：可配置、可审计、防刷、服务端权威。

## 2. 现有代码可复用能力

### 2.1 载具摧毁事件已存在
- `MCH_EntityAircraft.attackEntityFrom()` 内已在摧毁时抛出事件：`AircraftDestoryEvent`。  
- 事件字段包含 `attackerName` 与 `vehicleName`。  
- 可直接监听该事件并发放货币。

### 2.2 载具伤害事件已存在（可选）
- 同一方法中还有 `AircraftDamageEvent`，可用于“按伤害比例分配奖励”扩展。  
- MVP 阶段建议先只做击杀奖励，避免计算复杂化。

### 2.3 生物死亡事件尚未接入
- 当前事件钩子 `MCH_EventHook` 未实现 `LivingDeathEvent`。  
- 需要新增服务端监听器，基于 `LivingDeathEvent` 判断击杀归属并发放奖励。

### 2.4 关键注册点
- 当前在预初始化阶段已注册 `MCH_EventHook` 到 Forge 事件总线。  
- 可新增 `MCH_EconomyEventHandler` 并在同处注册，保持职责分离。

## 3. 推荐实现架构

### 3.1 新增模块
- `MCH_EconomyService`：统一发币接口与余额变更（加/减/审计）。
- `MCH_EconomyEventHandler`：监听 `LivingDeathEvent`、`AircraftDestoryEvent`。
- `MCH_EconomyConfig`：读取收益、倍率、上限、防刷配置。
- `MCH_EconomyAuditLog`：记录发币来源、对象、数量、时间、维度等。

### 3.2 事件流（建议）
1. 事件触发（生物死亡/载具摧毁）。  
2. 解析攻击者（必须归属到玩家）。  
3. 通过规则匹配收益表。  
4. 执行防刷校验（冷却、白名单、最小伤害占比等）。  
5. 调用 `MCH_EconomyService.grant()` 发放 `GE/SL/RP`。  
6. 写审计日志并向客户端提示。

## 4. 击杀归属判定方案

### 4.1 生物击杀归属（LivingDeathEvent）
- 主判定：`event.source.getEntity()` 为 `EntityPlayer` 时，归属该玩家。  
- 弹药击杀：当前弹药使用 `DamageSource.causeThrownDamage(this, shootingEntity)`，多数情况下可回溯到 `shootingEntity`。  
- 兼容判定：若直接实体不是玩家，但可追溯到玩家操控载具/座位，则归属该玩家。

### 4.2 载具摧毁归属（AircraftDestoryEvent）
- 现状只有 `attackerName`（字符串）。  
- 建议逻辑：通过 `world.getPlayerEntityByName(attackerName)` 获取在线玩家并结算。  
- 风险：名称变更或离线时可能丢失归属。  
- 优化建议：后续新增 `attackerUUID` 字段（V2）提升准确性。

## 5. 收益规则建议（默认）

### 5.1 生物击杀收益（示例）
- 普通怪：`SL +15 ~ +40`，`RP +5 ~ +12`，`GE 0`。  
- 精英/首领（如凋零、末影龙）：`SL +1000+`，`RP +400+`，`GE +1 ~ +5`（可配置开关）。

### 5.2 载具摧毁收益（示例）
- 按载具等级（T1/T2/T3）发放：  
  - T1：`SL +500`，`RP +120`，`GE +0`  
  - T2：`SL +1500`，`RP +350`，`GE +1`  
  - T3：`SL +3500`，`RP +800`，`GE +2`
- 可附加修正：跨级击杀奖励、连杀奖励、活动倍率。
- 建议优先支持“载具配置独立掉落区间（最小值/最大值）”，若未配置再回退到全局 T1/T2/T3 奖励表。
- 参数风格建议采用紧凑写法：`DestroyRewardSL=1200,2200`（你偏好的格式）。

### 5.3 收益上限建议
- 单次事件最大收益上限（防极端配置）。  
- 单日收益软上限（超过后收益衰减到 30%~50%）。

## 6. UI 图标与自适应缩放
- 图标目录约定：`mcheli/textures/coins/SL.png`、`mcheli/textures/coins/GE.png`、`mcheli/textures/coins/RP.png`。  
- 兼容说明：若历史文案使用 `RL`，显示层与配置层均映射到 `RP` 图标与字段。  
- 缩放策略：按屏幕高度基准自适应，例如 `scale = clamp(screenHeight / 1080.0, 0.75, 1.5)`。  
- 图标尺寸建议：基础 `16x16`，最终尺寸 `round(16 * scale)`，并限制最小 `12`、最大 `28`。  
- 文本与图标间距建议随 `scale` 线性缩放（如 `4 * scale`），防止高分辨率下拥挤。  
- 资源兜底：某货币图标缺失时回退到 `mcheli/textures/coins/default.png` 或直接文字显示。

## 7. 防刷与平衡策略（必须）
- 最小有效伤害占比：例如击杀者对目标累计伤害 >= 25% 才给全额收益。  
- 冷却限制：同一玩家对同类目标短时间重复击杀收益递减。  
- 目标去重：同一实体 ID 仅结算一次。  
- 友伤/同队过滤：同阵营目标不发放或低倍率。  
- 安全区过滤：出生保护区/脚本刷怪区可禁用收益。  
- 维度与生物白名单：只对配置允许的维度/实体生效。

## 8. 配置文件建议（可配置化）

建议新建：`资源文件/economy/reward_rules.txt`

```ini
EnableMobKillReward=true
; 是否启用生物击杀收益

EnableVehicleDestroyReward=true
; 是否启用载具摧毁收益

MobWhitelist=Zombie|Skeleton|Creeper|Spider|Enderman|Wither|EnderDragon
; 允许收益的生物注册名（简单名或全名，按实现统一）

MobReward=Zombie,20,0,8
; 生物收益格式：MobId,SL,GE,RP

MobReward=Wither,1800,2,600
; 首领收益示例

VehicleReward=T1,500,0,120
; 载具收益格式：Tier,SL,GE,RP

VehicleReward=T2,1500,1,350
; T2 收益

VehicleReward=T3,3500,2,800
; T3 收益

VehicleRewardUsePerVehicleRangeFirst=true
; 是否优先读取载具自身配置中的最小/最大奖励区间

MinDamageShare=0.25
; 最小有效伤害占比（0.25=25%）

RepeatKillDecayWindowTick=600
; 重复击杀衰减窗口（tick）

RepeatKillDecayFactor=0.50
; 衰减倍率（0.50=50%）

DailySoftCapSL=120000
; 每日 SL 软上限（超过后按衰减倍率）

DailySoftCapRP=60000
; 每日 RP 软上限

DailySoftCapGE=20
; 每日 GE 软上限

EnableAuditLog=true
; 是否记录发币审计日志
```

### 8.1 载具配置内独立掉落区间参数（推荐）
- 建议在每个载具配置（`资源文件/planes/*.txt`、`资源文件/tanks/*.txt`、`资源文件/helicopters/*.txt`、`资源文件/vehicles/*.txt`）增加以下参数：

```ini
DestroyRewardSL=800,1400
; 摧毁该载具时，SL 奖励区间：最小值,最大值

DestroyRewardGE=0,1
; 摧毁该载具时，GE 奖励区间：最小值,最大值

DestroyRewardRP=220,380
; 摧毁该载具时，RP 奖励区间：最小值,最大值
```

- 随机策略建议：闭区间整数随机 `rand(min, max)`。  
- 容错建议：当区间写反（如 `2200,1200`）时自动交换；当字段缺失时回退全局 `VehicleReward`。  
- 格式校验建议：必须是两个非负整数，非法时打印错误并回退全局奖励。  
- 兼容建议：若外部配置误写 `DestroyRewardRL=220,380`，在加载时自动映射为 `DestroyRewardRP` 并打印警告日志。  
- 向后兼容建议：旧格式 `DestroyRewardSLMin/Max` 仍可解析，但文档层面标记为“兼容旧写法，不再推荐”。

## 9. 实现步骤规划（含前端）

### 9.1 后端实现步骤
1. 扩展载具配置解析：支持 `DestroyRewardSL/GE/RP=min,max`。  
2. 扩展经济配置：保留全局 `VehicleReward=T?,SL,GE,RP` 作为回退。  
3. 接入事件发奖：监听 `AircraftDestoryEvent`、`LivingDeathEvent`。  
4. 接入发奖服务：统一经过 `EconomyService` 做校验、上限、审计。  
5. 完成持久化与同步：服务端存档余额，发奖后回包刷新客户端显示。  

### 9.2 前端页面实现步骤
1. 新建科技树 GUI 页面：货币栏 + 科技树画布 + 详情/操作区。  
2. 货币图标读取：`mcheli/textures/coins/SL.png|GE.png|RP.png`。  
3. 自适应缩放：按 `scale = clamp(screenHeight / 1080.0, 0.75, 1.5)` 统一控制图标、字体、间距。  
4. 交互请求走网络包：研发/购买/兑换全部由服务端校验后回包。  
5. 异常提示与兜底：余额不足、前置未解锁、图标缺失等统一提示。  

### 9.3 是否复用 MC 原版前端页面
- 结论：可借鉴，不建议直接复用。  
- 成就页（`GuiAchievements`）可借鉴点：树状节点排布、画布拖拽滚动。  
- 不建议直接复用原因：原版成就页数据模型绑定 `Achievement/Stat`，与“交易/货币/按钮操作”不匹配，改造成本高。  
- 推荐方案：复用交互思路，自建 `TechTreeGui` 渲染与数据绑定层。

## 10. 兼容与性能评估
- 事件驱动（死亡/摧毁）开销低，优于每 tick 轮询。  
- 关键开销点在“伤害占比统计”（若启用），建议使用短生命周期缓存并定时清理。  
- 审计日志建议异步写文件或按批次落盘，避免主线程抖动。

## 11. 风险与应对
- 风险：`attackerName` 仅字符串，离线时无法结算。  
  - 应对：先在线结算；V2 补 `UUID` 字段与离线缓存。  
- 风险：脚本刷怪导致经济膨胀。  
  - 应对：维度白名单 + 重复击杀衰减 + 每日软上限。  
- 风险：配置错误导致超发。  
  - 应对：加载期参数校验（负数、超上限、未知实体直接报错并禁用该条）。
- 风险：超高分辨率下 UI 图标过小/过大。  
  - 应对：统一 `clamp` 缩放与图标尺寸上下限。

## 12. 推荐落地顺序
1. 先做 `AircraftDestoryEvent` 发奖（最容易落地，收益明显）。  
2. 接入 `LivingDeathEvent`，完成怪物击杀收益。  
3. 增加载具配置内 `DestroyRewardSL/GE/RP=min,max` 区间奖励并接入回退逻辑。  
4. 加防刷（衰减/上限/白名单）。  
5. 完成科技树 GUI（含自适应缩放与货币图标）。  
6. 最后补“按伤害占比分配”与更细化经济平衡。

## 13. 分阶段实施与可复用代码映射

### 阶段 1：配置层落地（本次先执行）
- 目标：支持载具配置中的紧凑参数 `DestroyRewardSL=1200,2200`、`DestroyRewardGE=0,1`、`DestroyRewardRP=280,520`，并做容错（区间写反自动交换、非法回退、旧字段兼容）。  
- 复用代码：  
  - 参数拆分工具：`MCH_BaseInfo#splitParam`。  
  - 载具配置解析入口：`MCH_AircraftInfo#loadItemData`（飞机/坦克/直升机/车辆均走该基类解析链）。  
  - 现有逗号参数风格示例：`RepairOtherVehicles`、`RadarGainFactor`、`RadarRCSFactor`。  
- 交付物：载具信息对象内可读取到奖励区间字段（供后续事件发奖阶段调用）。

### 阶段 2：事件接入与发奖入口
- 目标：接入 `AircraftDestoryEvent` + `LivingDeathEvent`，把“触发发奖”链路打通。  
- 复用代码：  
  - 载具摧毁事件：`AircraftDestoryEvent`（已存在触发点）。  
  - 事件总线注册点：`MCH_MOD#PreInit`（已注册 `MCH_EventHook`，可并列注册经济处理器）。  
  - 通用事件类：`MCH_EventHook`（可参考其事件订阅写法）。

### 阶段 3：归属判定与经济服务
- 目标：统一“奖励给谁”的判定与服务端发币逻辑。  
- 复用代码：  
  - 弹药攻击者来源：`MCH_EntityBaseBullet.shootingEntity / shootingAircraft`。  
  - 伤害来源链路：`DamageSource.causeThrownDamage(this, shootingEntity)`。  
  - 可复用命名与结构：按 MCH 现有 Service/Manager 风格新增 `EconomyService`。

### 阶段 4：货币持久化与网络同步
- 目标：服务端权威存档（SL/GE/RP），客户端只做显示。  
- 复用代码：  
  - 网络包基础设施：`PacketBase`、`PacketHandler`、`sendTo/sendToServer`。  
  - 同步包范式：`PacketEntityInfoSync`（可参考编码/解码/下发模式）。
- 本轮实施结果（已完成）：  
  - 服务端持久化：`MCH_EconomyService` 基于玩家 `NBT`（`MCH_Economy`）持久保存 `SL/GE/RP`。  
  - 同步协议：新增 `MCH_PacketNotifyEconomySync`，下发当前余额 `sl/ge/rp`。  
  - 包分发接入：`MCH_Packet` 新增 `MSGID_NOTIFY_ECONOMY_SYNC=268437569`，`MCH_PacketHandler` 增加对应分发。  
  - 客户端缓存：新增 `MCH_EconomyClientData`，由 `MCH_EconomyPacketHandler` 在客户端更新显示数据。  
  - 同步时机：发奖后自动同步；玩家进服（`EntityJoinWorldEvent`）自动同步一次初始余额。

### 阶段 5：科技树/NPC 后端
- 目标：实现 RP 解锁、SL 购买、GE 特购/兑换，以及前置依赖校验。  
- 复用代码：  
  - NPC 配置体系：`MCH_GunnerInfo` / `MCH_GunnerInfoManager`。  
  - 生成链路：`MCH_ConfigSpawnerTileEntity`（可扩展村庄随机刷 NPC 规则）。
- 本轮实施结果（已完成）：  
  - 节点模型与注册：新增 `MCH_EconomyTechNode`、`MCH_EconomyTechRegistry`。  
  - NPC 节点自动注册：从 `MCH_GunnerInfoManager.getValues()` 自动生成 `npc.<itemName>` 的 `SL_PURCHASE` 节点。  
  - 前置依赖校验：`SL_PURCHASE` 默认依赖 `core.gunner_license`（`RP_UNLOCK`）。  
  - 货币操作链路：新增 `MCH_EconomyTechService`，统一执行 `RP 解锁 / SL 购买 / GE 兑换` 与 NBT 持久化。  
  - 网络后端接口：新增 `MCH_PacketIndEconomyTechAction`（C2S 请求）与 `MCH_PacketNotifyEconomyTechResult`（S2C 回包），并接入主包分发。  
  - 余额扣费能力：`MCH_EconomyService` 新增 `trySpend(...)`，与发奖链路共享服务端权威记账与同步。

### 阶段 6：前端 GUI（科技树与货币条）
- 目标：自建 GUI，完成科技树页面、货币展示与按钮交互。
