# 航路点标记方块功能需求提炼（基于对话）

日期：2026-04-16  
范围：仅需求提炼与方案文档，不改代码

---

## 1. 目标（从对话提炼）

- 你希望新增一个“航路点标记方块”体系，用于让载具按预设路线循环巡逻。
- 载具不是随机找点，而是按固定链路前进：`生成器 -> A -> B -> C -> A -> ...`。
- 每个航路点有“驻留/巡逻时间”，到点后会停留一段时间再前往下一个点。
- 载具生成方块需要能指定“初始目标航路点”（例如初始目标为 A）。
- 空中载具的到点判定不是点判定，而是“圆柱范围判定”（半径 + 高度）。

---

## 2. 你想要的核心流程（与你对话一致）

标准时序：

1. 载具由生成器生成。  
2. 读取生成器配置的初始航路点（例如 A）。  
3. 载具前往 A。  
4. 进入 A 的判定范围后，开始在 A 巡逻/驻留 `PatrolTime`。  
5. 到时后读取 A 的 `NextWaypoint=B`，前往 B。  
6. 同理到 B 后驻留，再前往 C。  
7. 到 C 后驻留，再前往 A。  
8. 无限循环。

对应你明确表达的链路：

`出生 -> A -> (A停留) -> B -> (B停留) -> C -> (C停留) -> A`

---

## 3. 功能模型（建议）

### 3.1 对象与职责

- 载具生成器方块：
  - 决定“是否启用航路逻辑”
  - 指定“初始航路点 ID”
- 航路点方块：
  - 定义自己的判定范围
  - 定义本点驻留时间
  - 定义下一航路点 ID（形成链）
- 载具巡逻状态：
  - 当前目标点
  - 是否处于驻留阶段
  - 驻留剩余时间

### 3.2 到点判定

- 地面载具：可用水平半径或球形半径（建议先水平半径）。
- 空中载具：按你要求使用圆柱判定：
  - 水平半径 `Radius`
  - 高度范围 `Height`（或上下半高）

---

## 4. 配置提案（仅文档草案）

### 4.1 载具生成器方块扩展参数（blocks/*.txt）

- `EnableWaypointPatrol=true|false`  
  - 是否启用航路巡逻
- `InitialWaypointId=<id>`  
  - 初始目标航路点（如 `wp_a`）
- `WaypointFailAction=hold|despawn|return`（可选）  
  - 初始点缺失时策略（建议默认 `hold`）

### 4.2 航路点方块参数（waypoints/*.txt 或 blocks/*.txt 扩展）

- `WaypointId=<id>`  
  - 当前航路点唯一 ID
- `NextWaypointId=<id>`  
  - 下一航路点 ID
- `PatrolTimeTick=<tick>`  
  - 到点后驻留时间
- `Radius=<double>`  
  - 水平判定半径
- `Height=<double>`  
  - 空中圆柱判定高度
- `ArrivalToleranceY=<double>`（可选）  
  - 对地面载具的 Y 轴容差

---

## 5. 状态机提案（便于后续实现）

建议载具巡逻采用 3 态：

- `NAVIGATE`
  - 朝当前目标航路点移动
  - 进入判定范围后切换到 `HOLD`
- `HOLD`
  - 开始驻留计时
  - 计时结束后读取 `NextWaypointId`，切换到 `NAVIGATE`
- `ERROR`
  - 目标点缺失或链断裂时进入异常态
  - 按 `WaypointFailAction` 执行

---

## 6. 你当前想法与方案符合度评估

### 6.1 完全符合的点

- 非随机路径，而是固定链式巡逻。
- 生成器指定初始航路点。
- 每个航路点可配置巡逻/驻留时间。
- 空中载具用“圆柱范围”判定到点。

### 6.2 还需要你补充决策的点

- 航路点方块是否独立文件目录（推荐独立 `waypoints`）。
- 链断裂时的处理策略（停留原地/返航/销毁）。
- 多载具同时使用同一路点是否需要“占位/排队”。
- 空中圆柱高度是“总高”还是“上下各半高”。

---

## 7. 最小可行版本（MVP）建议

第一版先做最小闭环：

1. 生成器支持 `InitialWaypointId`。  
2. 航路点支持 `WaypointId/NextWaypointId/PatrolTimeTick/Radius/Height`。  
3. 载具按 `NAVIGATE -> HOLD -> NAVIGATE` 循环。  
4. 空中到点使用圆柱判定。  
5. 链断裂先“停留原地 + 打日志”。

这样可以最快验证你的核心玩法是不是你想要的感觉。
